# Releases

Every Seedelf Wallet package uploaded to the Chrome Web Store: the commit it was built from, the zip's SHA-256, and its tag. Seedelf Wallet is a Cardano wallet for Chrome with a private balance built in; this page is for anyone who wants to check that a package is what its commit builds. The source is at <https://github.com/logical-mechanism/Seedelf-Wallet>, and what each feature is, in the wallet's [README](../README.md) and [privacy.md](privacy.md).

From 1.6.0 on, each release is tagged `web-wallet/<version>` on its commit. The tags are plain git tags, not signed. [SECURITY.md](../../../SECURITY.md)'s bounty scope is the latest such tag.

## Checking a package

What you can check is that a release's commit builds the zip this table records. The table records the zip uploaded to the Chrome Web Store; Chrome installs the store's signed package, not that zip, and nothing in this repository describes comparing an installed copy with the table.

1. **Check out the release's tag**, or before 1.6.0 its commit, in a clean clone of <https://github.com/logical-mechanism/Seedelf-Wallet>.
2. **Install the toolchain** the WebAssembly build needs (`seedelf-platform/seedelf-web-wallet/wasm/build.sh` says what's missing):
   - Rust 1.98.1, with its `wasm32-unknown-unknown` target: what every release's `seedelf-platform/rust-toolchain.toml` pins;
   - `wasm-bindgen-cli` 0.2.128, the version every release's `seedelf-platform/Cargo.lock` records for `wasm-bindgen`;
   - `clang` with a wasm32 backend, and `llvm-ar`;
   - an official Node build, 22 or later (`package.json`'s `engines`).
3. **Build it:** in `seedelf-platform/seedelf-web-wallet/extension/`, run `npm ci`, then `npm run package`. It writes `release/seedelf-wallet-<version>-mainnet.zip` and prints `sha256 <hex>`.
4. **Compare** that hash with the table's.

**What's pinned, and what isn't.** Pinned: the Rust version (`rust-toolchain.toml`), every Rust crate (`Cargo.lock`, built `--locked`), every npm package (`package-lock.json`, through `npm ci`), and `wasm-bindgen-cli`, which must match `Cargo.lock`. Not pinned: `clang`, which compiles the C code of blst (the BLS12-381 library) and is whichever is on your `PATH`, so a different `clang` can change the bytes; and Node, though official Node builds 20 to 24 zip alike, and one linked to the system's zlib may not. So the same commit gives the same bytes with the same `clang` and an official Node build. The releases from 1.7.2 on were built with `Ubuntu clang version 21.1.8 (6ubuntu1)` and Node 24.19.0 (zlib 1.3.2.1-motley-3246f1b).

For maintainers: how a release is recorded, and each release's record, with the toolchain lines its build printed, is in [plans/release-records.md](plans/release-records.md). The steps of a release are in [development.md](development.md#releasing-to-the-web-store).
