# Releases

Every Seedelf Wallet package uploaded to the Chrome Web Store: the commit it was built from and the zip's SHA-256. The package is reproducible, so anyone can build that commit with the pinned toolchain and compare ([development.md](development.md#releasing-to-the-web-store), step 8). From 1.6.0 on, each is tagged `web-wallet/<version>` on that commit, and [SECURITY.md](../../../SECURITY.md)'s bounty scope is the latest such tag.

**No dates, and nothing about what the store is doing** (the owner, 2026-10-04): review takes as long as it takes, and a doc that says what's live is wrong as soon as it changes.

## Recording a release

The release's record PR, after the upload ([development.md](development.md#releasing-to-the-web-store)'s last step), adds a row to the table and a section below it, newest first, headed by the version. The section says:

- **The branch and what it carried:** the PRs, the plans they built, and the review's record in [archive/plans/](archive/plans/) if there was one.
- **The lists** each release refreshes: the tokens, the DReps, the Lovejoin pools' head start and their Cardanoscan names, and the data layer's token decimals; what changed, or that nothing did.
- **The translations** that changed, and how each was checked; and the privacy policy's entry, if it owed one.
- **The checks** run on the merged tree, and whether the data layer's API was deployed, and from which commit.
- **The package:** the commit it was built from, the zip's SHA-256, its size, and the `C compiler`, Node and zlib lines the build printed; and that a second build of the same commit gave the same bytes.
- **The tag**, and anything that surprised the release: what a later session would lose time over without it.
- **What it left open** goes into [backlog.md](backlog.md) as a line, not here.

## Records

### 1.8.1

- **The branch and what it carried:** a patch. Lovejoin's transactions take whatever sits in their pool's `mix_logic` reward account, which anyone can pay into and which, until someone takes it all, makes the ledger refuse every mix and way back in that pool; and the dApp signer refuses a site's transaction that pays into one (#367, [chunk 43](archive/plans/chunk-43-lovejoin-reward-balance.md)). Also on `main` since 1.8.0: 1.8.0's record (#366), and Lovejoin v2's `mix_logic` and `one_shot_mint` proven in every transaction, with what we claim in `seedelf-verification/CLAIMS.md` (#368, [chunk 45](archive/plans/chunk-45-lovejoin-every-tx.md)), which isn't in the extension. The gate, `web-wallet/release-1.8.1` (#369), reviewed #367 and #368 as one tree and fixed what it found, and merged as `f77aa5c1`. Its main find: since protocol version 11 the ledger calls a withdrawal short of the account's balance `ConwayIncompleteWithdrawals`, so #367's refusal never fired, and staking's "rewards changed" words had never shown since the hard fork; both do now. [archive/plans/review-1.8.1.md](archive/plans/review-1.8.1.md) is the review's record.
- **The lists:** tokens unchanged (2 preprod, 32 mainnet), and so are the data layer's token decimals (1,175). Named DReps: mainnet 466 (one kept as committed), preprod 63; only the dates moved. The head start gains mainnet's v2 5 ₳ pool (`fcb3f5ec…`, launched at block 14,167,059), for 2 mainnet pools; preprod's 5 are unchanged. Its four Cardanoscan entries ("Mix Box v2 (5 ADA)" and the rest, version 3) are new and not sent: the owner's fork still holds the 8131b1d 5 ₳ pool's four (`dc6abe3b…`) as an uncommitted change, so part 1's registry block refuses until it's committed or discarded.
- **The translations:** `lj.rewardsMovedReview`, `lj.warn.rewardsMoved` and `dapp.lovejoinRewards` are new, in en, es and ja (#367). `lj.warn.rewardsMoved` is critical: it was back-translated blind in es and ja at chunk 43, and again by the review in two rounds, for the eight places it now shows, with no drift ([verified-critical-es.json](i18n/verified-critical-es.json) and [-ja](i18n/verified-critical-ja.json) say so). The store listing's text is unchanged. The privacy policy's entry is dated 6 November 2026: a Lovejoin pool's reward account read before a mix or a box's way back.
- **The checks,** on #369's final tree, which is the merge's: Rust fmt, clippy `-D warnings`, the workspace's 745 tests and the ignored `payment_parts_shapes_test` in a release build; `./check.sh lovejoin-every`, 76 ok; `tsc` clean; Vitest 3,261 on both builds; e2e 108 on the dev and store builds, and the data layer's 3; and a live run on preprod, which took the PV11 refusal end to end through the real node ([The live run](archive/plans/review-1.8.1.md#the-live-run)). **No API deploy:** neither `seedelf-data/` nor `src/tokens/list.json` changed since `web-wallet/1.8.0`.
- **The package:** `seedelf-wallet-1.8.1-mainnet.zip`, built from `f77aa5c1` with Node 24.19.0 (zlib 1.3.2.1-motley-3246f1b) and `C compiler: Ubuntu clang version 21.1.8 (6ubuntu1)`: **SHA-256 `cf745c2485a523b734651d4954b4128e2bdf215d9f682f304828de9d60a18628`** (2,116,417 bytes, 24 files). A second build of the same commit, in a worktree of its own with its own `node_modules` and cargo target, gave the same bytes. The whole e2e suite passed on it (108). Not in it: what checklist item 9 found, which only the owner has.
- **The tag:** `web-wallet/1.8.1`, on `f77aa5c1`. What surprised the release: e2e's "a 5 ₳ pool launched after the head start on mainnet" test skips now, as it was written to, since mainnet's v2 5 ₳ pool is bundled: 108 passed and 1 skipped is the whole suite, not a lost test. And the review's live run left preprod wallet A's box `2aa41377…#0` in pool `47bece42…` behind a two-hour hold (a withdraw held as maybe sent after a Koios 500); it comes back by itself on a later run of A. The review's [Lessons](archive/plans/review-1.8.1.md#lessons) cover the rest.
