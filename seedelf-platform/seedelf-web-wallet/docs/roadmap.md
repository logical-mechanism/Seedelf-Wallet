- **2026-10-04: chunk 20, NFT images** (`web-wallet/nft-images`). [post-release-roadmap.md](post-release-roadmap.md#p3--nft-images)'s P3, the last of feature parity, and the plan is [archive/plans/chunk-20-nft-images.md](archive/plans/chunk-20-nft-images.md). **Show image** in an NFT's details: one Koios `asset_info` (both standards in two columns: CIP-68's reference datum under `"222"`, CIP-25's label 721), then one fetch from IPFS. **The surprise: the public IPFS gateways are mostly gone.** `ipfs.io` and `dweb.link` answer 429, "switching to a service worker gateway only", and of about twenty tried only **`ipfs.blockfrost.dev`** served the file, which is Lace's too. **It sends no CORS headers, and that decided the design:** an `<img src>` would have worked with no grant, but it writes the image, and an address naming the NFT, to Chrome's disk cache for a year, and sends the host's cookies. So the worker fetches with `cache: "no-store"` and no credentials, through Chrome's grant for that one host, asked by the page at the first click. That host is a part of the dApp connector's optional `https://*/*`, so the manifest's permissions are byte-for-byte the same and only `connect-src` grew. **A request without the grant still reaches the gateway; only its answer is blocked.** So the worker checks the grant before it asks anyone, Koios included. **Only IPFS is fetched**, because anyone can send you an NFT whose image is on a server of theirs; another gateway's `/ipfs/<cid>` address is rewritten to Blockfrost's, since it's the same file. The images live in the page's memory until the lock. **Real metadata is messier than the CIPs:** `mediaType: "image/jpg"`, `image: "ipfs://"` with no CID, a 222-labelled NFT with no reference datum at all, a CIDv1 in base58; the test account's NFTs have all of them, recorded by `tests/fixtures/record-nft-images.mjs`. **The blind back-translation found the Settings line's Spanish "No tiene cuentas"** read as "the wallet has no accounts" beside "cuenta pública", a slip from chunk 19 that this chunk's edit to that key surfaced. - **2026-10-03: chunk 19, language** (`web-wallet/language`). [post-release-roadmap.md](post-release-roadmap.md#p2--language)'s P2, and the plan is [archive/plans/chunk-19-language.md](archive/plans/chunk-19-language.md). All 2,471 strings out of source into `en`, `es` and `ja`; i18next alone, which has **no transitive dependencies**, so the whole chunk cost one MIT package. **What made a 2,471-string bulk change safe was that the ~120 vitest files assert on *rendered* English**: initialise i18next synchronously at import, in English, and they pass untouched — which promoted "English is byte-identical" to the acceptance test, and it held through every commit. **The trap is any module-level `const` holding a sentence**: ES imports run before `main.tsx` awaits the stored language, so an eager `t()` binds English for the session's life. Fourteen of them existed; all are functions now, and four were missed by the first audit because their `t()` sat on the next line. **English word order was load-bearing in about twenty places** (`many ?
