# PR #332: overflow checks for core, crypto and koios in `wasm-release` (label `pr332`)

Merge `4610555a`. Diff: `Cargo.toml` (three `[profile.wasm-release.package.*] overflow-checks = true`), four comments, `CLAUDE.md`, the roadmap.

## Verdict

**The change is safe to ship.** The profile syntax is valid. `wasm/build.sh` builds with `--profile wasm-release` (line 61), and so do CI (`web-wallet.yml:80`) and `npm run package`, so the overrides reach the store's module. I found no new trap on outside data. Every non-test arithmetic site in seedelf-core, -crypto and -koios (176, listed below) is one of:

- checked by hand (`Asset::add`, `Assets::merge`, `assets_of`, `select`, `fitting`, 314-core#1's planner sums, the CBOR walk's `checked_mul`);
- bounded:
  - real lovelace stays under the ADA supply;
  - a pool's box rows must hold exactly its value (`PoolBox::from_row`);
  - parameters are capped in `from_koios`, and `ProtocolParameters` has no `Deserialize` to get round the caps;
  - budgets come from the local evaluator;
  - depth is held to 0..=3 and width to {3, 4};
- or inside one row.

Nothing in the three crates relies on wrapping (no hash, PRNG or bit trick with a plain operator: XORs, in-range `u8` shifts, `HARDENED |`).

**But the module doesn't do quite what the PR, its comments and CLAUDE.md say.** Overflow checks follow the crate that *compiles* the code, not the crate that defines it, so the line isn't the crate line (F1). Also, nothing fails if the overrides go (F2).

## Findings

### F1 (low, docs/correctness): core leaf and generic code called from seedelf-wasm still wraps, and some of seedelf-wasm's own sums now trap

**Claim.** On the pinned rustc 1.98.1, with `wasm-release` (opt-level z, fat LTO, one codegen unit), an overflow assert survives only where the codegenning crate has checks on.

- (a) A small call-free core function is codegen'd in seedelf-wasm and wraps: rustc's automatic cross-crate inlining hands it to the caller. So is a generic core function instantiated with seedelf-wasm's types or closures, and so would be an `#[inline]` one.
- (b) The reverse also holds. seedelf-wasm's own `.iter().sum()` over an iterator type core already sums links to core's checked instance (shared generics) and traps.

**Evidence: HEAD's crates.** I copied HEAD to scratch and added probe exports to the copy's seedelf-wasm only. Built with `cargo build --locked --target wasm32-unknown-unknown --profile wasm-release`, run through wasm-bindgen into scratch, called from node:

| Probe | Code | Result |
|---|---|---|
| `Locked { reference: u64::MAX, mix_box: 1, .. }.total()` | core, `launch.rs:90-92`: `self.reference + self.mix_box + self.mix_logic + self.deposit`; called from seedelf-wasm at `lib.rs:2627`, `2713` | **returned 0** (wrapped) |
| `total_computation_fee(&params, vec![(u64::MAX, u64::MAX); 20])` | core, `transaction.rs:189-194` (it has calls in it) | `RuntimeError: unreachable` |
| `vec![u64::MAX, 1].iter().sum::<u64>()` in seedelf-wasm | the same `<u64 as Sum<&u64>>::sum::<slice::Iter<u64>>` core makes (e.g. `build.rs:1067` `lovelace: paid.iter().sum()`) | **`RuntimeError: unreachable`** (checked) |
| `u64::MAX + 1` in seedelf-wasm | seedelf-wasm | returned 0 |

**Evidence: a two-crate reproduction.** Same profile, wasm32, crate `a` with checks on and `c` with them off:

- Wrapped: a plain leaf, a `#[inline]` fn, a generic fn, an `impl Fn` fn, a leaf with a variable division, a struct's leaf method (`Locked::total`'s shape).
- Trapped: functions holding a call (`.sum()`, `pow`, `div_ceil`, a helper) and an `#[inline(never)]` one.
- `c`'s `.iter().sum()` over `&[u64]` trapped when `a` instantiates the same, and its `into_iter().sum()` wrapped.

**Where the docs draw the crate line:**

- `Cargo.toml:44` "Core, crypto and koios check integer overflow in the module".
- `CLAUDE.md:94` "Its per-package overrides check integer overflow in `seedelf-core`, `-crypto` and `-koios` (a trap that locks the wallet, not a wrapped sum), but not in `seedelf-wasm`".
- `post-release-roadmap.md:387` "core's, crypto's and koios's overflow is checked in the module too … so a sum past its type traps".
- `lovejoin/mod.rs:1758-1760` (`MORE_THAN_THERE_IS`) "Since 1.7.0 the module checks core's … so one missed would trap and lock the wallet".

**Scenario.** There's no live case today:

- The leaf core helpers seedelf-wasm calls (`Locked::total`, `eval::slot_at`, `lovejoin::mix_fee_estimate`; `build::linear_fee` saturates) see only bounded values.
- seedelf-wasm's plain sums go through its own closures (crate-local, unchecked) or add `usize` box counts.

The hazard is the next change, made by the documented rule. A developer adds a small helper in core on a pool datum's value, say `p.denom * n`. They leave out `checked_mul` because CLAUDE.md says core traps, and call the helper from seedelf-wasm. In the store's module it's compiled into seedelf-wasm and wraps to a small, false figure while every test build panics. That is 314-core#1 / x-release#7, the gap this PR closes. Conversely, a seedelf-wasm sum the comments say wraps can trap and lock.

**Fix.** Say the real rule in the four places:

- What's checked: core's arithmetic, where core's own code compiles it.
- What still wraps: a small call-free core function, or a generic one, that seedelf-wasm calls. It's compiled in seedelf-wasm.
- What may trap: a sum seedelf-wasm makes over an iterator type core also sums.
- The rule that holds both ways: values from outside the wallet are summed with `checked_*` in every crate.

`architecture.md:99` and `wasm/README.md:115` describe the profile without its overrides and could say so too.

**Confidence:** high (measured on HEAD's code with the shipped profile and toolchain).

### F2 (low, tests): nothing fails without the overrides

**Claim.** The PR's behaviour has no test. Its probe was built and removed, and every existing test passes with or without the three sections:

- the Rust tests run in debug, checked either way;
- the WebAssembly node tests and Vitest passed on the unchecked module before the PR.

A tidy-up of `Cargo.toml`, or a toolchain bump that moves more of core into seedelf-wasm's codegen, would ship a wrapping module with CI green.

**Evidence.** HEAD's crates built in scratch with the three sections removed contain **0** occurrences of `attempt to add with overflow`, `attempt to subtract with overflow` and `attempt to multiply with overflow`. The tree's HEAD module (`wasm/pkg/seedelf_wasm_bg.wasm`) has **1** of each. Only overflow-checked code references those panic messages.

**Fix.** At the end of `wasm/build.sh`, beside its local-path check:

```bash
grep -aq "attempt to add with overflow" "$wasm" || { echo "The module carries no overflow check: Cargo.toml's wasm-release overrides are gone" >&2; exit 1; }
```

It's crude: it says some code is checked, not which (see F1). It is what fails without the overrides.

**Test.** That line. Without the overrides `build.sh` exits 1; with them it passes (counts above).

**Confidence:** high.
