# e4b#1: verification

From lane E4b, graded low by its finder.

## Trace: confirmed, low

It holds as described. When the connector's window opens on an unlocked wallet, App tells the worker the user is active before anything is pressed. A site's enable() opens that window with no gesture: an unconnected site's enable(), or a connected site's signData, signTx or first CIP-95 enable(). A reload then ends the request with no refusal, and the empty window closes itself after 0.8 s, so the next enable() opens a new window, which reports again. Run every 14 minutes, the 15-minute auto-lock never comes for as long as the tab stays open. There is no cap on how often a site can open the window.

I found no guard: no connectorWindow check on the mount-time report, no user-gesture or visibility check in page.ts, and gone() never calls refuseFor. No test covers it either way, and it isn't known: nothing in the backlog, the archived reviews' Not fixed or Left open lists, chunk 46, chunk 49 or SECURITY.md covers it. architecture.md:556 promises the opposite: "a site's calls never count as activity, so auto-lock ends it".

Why low:
- **Who can reach it:** any https site in a tab, connected or not, once the user has turned the connector on (it's off by default).
- **What it costs:** auto-lock stops working. Money is at risk only if a second person reaches the unattended browser, because the wallet's own Send needs no password while unlocked. A connected site's reads also keep being answered while the user is away.
- **The way out:** the Lock button, closing the tab, or turning the connector off. A user who is present sees a focused popup flash on each cycle.

The site itself can't take funds or a key.

**Evidence:**

The trace, from where the input enters to the outcome (all paths under seedelf-platform/seedelf-web-wallet/extension/src):

1. **The site's call.** `content/page.ts:85-87` `enable` posts to the bridge. `content/bridge.ts:44-71` uses one port per page. `background/sw.ts:388-430` checks the port (`dappSession`, `sw.ts:363-369`: a top frame on https gets a fresh `randomUUID` session) and calls `answerSite`.
2. **Opening the window.** `dapp.ts:546` `call` → `run` (`569-585`): with the connector on and the wallet unlocked, it calls `enable` (`1059`). An unconnected origin with no waiting connect (`1075`) and no refusal (`1089`) goes to `ask` (`1100`). `ask` (`1553-1597`) pushes to `waiting`, calls `changed()`, then `this.deps.window.show()`. `dapp-window.ts:20-33`: with no `?view=dapp` page open, it runs `chrome.windows.create({ url: index.html?view=dapp, type: "popup", focused: true })`.
3. **The mount-time report.** `ui/view.ts:13`: `connectorWindow` is true. `ui/App.tsx:54-57` asks for the status, and `:77` sets `unlocked`. `:92-100` then runs `if (!unlocked) return; reportActivity();` with no `connectorWindow` check. `App.tsx:155` gates only the screen on it.
4. **No throttle on a new page.** `ui/background.ts:110-119`: `lastActivity = 0` per page, so a new window's first report always goes out as `call("activity")`.
5. **The worker pushes the lock back.** `handlers.ts:184-186` calls `wallet.touch()`. `wallet.ts:360-366` sets `SESSION_ACTIVITY` (`"seedelf.lastActivity"`, `:61`) to now. `wallet.ts:615-645` `load()` stays unlocked while `idle < lockAfter`. The alarm (`sw.ts:443-458`) and `status` (`handlers.ts:650-651`) both go through `load()`.
6. **The reload.** The port disconnects: `sw.ts:431-434` → `dapp.ts:873-886` `gone()` rejects with `PAGE_GONE`, with no `refuseFor`, and calls `changed()`. `DappApprovals.tsx:94-97` reloads the approvals (an empty list). `:101-114`, after `CLOSE_AFTER_MS` (800 ms, `:60`), calls `dapp-close` (`handlers.ts:437-438`) → `dapp.ts:748-758` `closeWindow`. `dapp.ts:765-769` `windowClosed`, with nothing waiting, records no refusal. `show()` is never cancelled by `gone()`, so even an early reload still gets a window that mounts and reports.
7. **The next call** comes from a new page and a new session: there's no waiting connect and no refusal, so a new window opens and reports again.
8. **No cap.** `PER_MINUTE` (`dapp.ts:235`) counts only Koios lookups, submits and unprompted reads. `MAX_WAITING` and `MAX_SITE_WAITING` count only what's waiting.
9. **Nothing else reports activity on its own.** `LockCountdown`'s asks (`lock-deadline`, `chains-sending`, `parts-waiting`) are not activity, and `stayUnlocked` needs a click.
10. **The design and the cost.**
   - The chunk 5 plan, line 103: "The UI sends throttled `activity` pings while the user interacts."
   - `docs/architecture.md:556` says the opposite of what happens.
   - The blind test, line 381: "No password on Send is intended". Only site signatures, reveal-phrase and change-password take a password while unlocked.
   - Defaults (`shared/preferences.ts`): `dappConnector: false`, `lockAfterMinutes: 15`.

**Fix notes:**

**The fix.** The finder's sketch works as written. At `ui/App.tsx:94`, report activity on mount only outside the connector's window: `if (!connectorWindow) reportActivity();`. Keep the pointerdown and keydown listeners, so a click on Connect or Sign still reports; test 2 pins that. Nothing is lost when the user unlocks in the window, because `wallet.ts:663` (`open()`) sets the last activity at the unlock itself.

**The class.** The only page the worker opens without being asked is this window (`dapp-window.ts:30`; `view.ts:21` and `open-in.ts:54` are user clicks). None of the window's other automatic requests is activity: status, dapp-approvals, preferences, accounts, lock-deadline, chains-sending, parts-waiting and dapp-close.

**Docs.** After the fix, `architecture.md:556` ("a site's calls never count as activity") becomes true. `architecture.md:450` could add that the connector's window counts only a click or a key.

**Owner sign-off.** The change needs none: it adds no refusal and changes no privacy default and no screen.

**For the owner, separately (the finder's note, confirmed in the trace).** `gone()` (`dapp.ts:873-886`) doesn't count a page that leaves before the user answers as a decline. So a site that reloads escapes the L35 back-off and can pop the focused window as often as it reloads. Counting that as a decline would change what dApps see on an ordinary reload, which is the owner's call.

**Test-shape caveat.** The test reads what the page sends, so it pins a page-side fix. A fix that let the page still send `activity` and had the worker ignore it would fail the test.

// Chunk 51, finding e4b#1: a site can keep the wallet from auto-locking. A site's `enable()` opens the connector's
// window (dapp.ts `ask` → dapp-window.ts `show`: a new focused popup when none is open), and that window is App at
// `?view=dapp`, which tells the worker the user is active the moment it mounts unlocked (App.tsx:92-100), before
// anything is pressed. The site then reloads: its request ends with no refusal (`gone`), the empty window closes
// itself after 0.8 s, and the next `enable()` opens a new window, which reports again. Done every 14 minutes, the
// 15-minute auto-lock never comes. The right behaviour: the connector's window counts only input (a click or a key)
// as activity, never its own opening, which a site can cause.

// lands in the same render; what App draws under it is made as nothing. What the page sends the worker through
// ui/background.ts's own `call` (reportActivity's) is read off chrome's port.

const seam = vi.hoisted(() => {
  type Ok = ((value: unknown) => unknown) | null | undefined;
  type No = ((error: unknown) => unknown) | null | undefined;
  /** A thenable that answers at once, as `call` does here: an effect's `.then` lands in the same render. */
  interface Answer {
    then(ok?: Ok, no?: No): Answer;
    catch(no: No): Answer;
    finally(done: () => void): Answer;
  }
  const isAnswer = (v: unknown): v is Answer => !!v && typeof (v as Answer).then === "function";
  const lift = (v: unknown): Answer => (isAnswer(v) ? v : settled(v));
  function settled(value: unknown): Answer {
    return {
      then: (ok) => {
        try {
          return ok ? lift(ok(value)) : settled(value);
        } catch (e) {
          return failed(e);
        }
      },
      catch: () => settled(value),
      finally: (done) => {
        done();
        return settled(value);
      },
    };
  }
  function failed(error: unknown): Answer {
    return {
      then: (_ok, no) => (no ? lift(no(error)) : failed(error)),
      catch: (no) => (no ? lift(no(error)) : failed(error)),
      finally: (done) => {
        done();
        return failed(error);
      },
    };
  }
  /** Never answers: a request the test leaves unanswered. */
  const pending: Answer = { then: () => pending, catch: () => pending, finally: () => pending };

  const state = {
    /** The components whose own effects run: App's alone, never a child's or a custom hook's. */
    effects: new Set<string>(["App"]),
    /** Components made as nothing: everything App draws sits under AccountsProvider. */
    stubbed: new Set<string>(["AccountsProvider"]),
    /** What the worker answers, by request. */
    answers: new Map<string, unknown>(),
    /** App's own requests, through the `call` it imports, in order. */
    asked: [] as string[],
    /** What went out on chrome's ports: ui/background.ts's own `call`, which reportActivity uses. */
    posted: [] as string[],
    /** The page's window listeners, by event. */
    listeners: new Map<string, Array<() => void>>(),

    call(type: string): Answer {
      state.asked.push(type);
      return state.answers.has(type) ? lift(state.answers.get(type)) : pending;
    },

    /** The JSX runtime's element factories, with `stubbed` in them. */
    runtime<R extends Record<string, unknown>>(runtime: R): R {
      const named = (type: unknown) => (typeof type === "string" ? type : typeof type === "function" ? type.name : "");
      const Stub = () => null;
      const wrap =
        (create: (...args: unknown[]) => unknown) =>
        (type: unknown, ...rest: unknown[]) =>
          create(state.stubbed.has(named(type)) ? Stub : type, ...rest);
      const out: Record<string, unknown> = { ...runtime };
      for (const key of ["jsx", "jsxs", "jsxDEV"]) if (typeof runtime[key] === "function") out[key] = wrap(runtime[key] as (...args: unknown[]) => unknown);
      return out as R;
    },
  };
  return state;
});
