## Trace: confirmed, low

The finding holds as described. The signing page does not find the witness set by position. It searches the whole unsigned transaction hex, nibble by nibble, for the first "a105" (and failing that, the first "a0f5f6") and splices the wallet's witnesses in at that point. I looked for something that would stop the path and found nothing:
- web_server.rs:64-66 injects the hex unchanged.
- The three callers (create.rs:260, fund.rs:277, extract.rs:285) all pass hex::encode of the raw transaction.
- The page has no other branch.
- Pallas 0.35.1 writes `84 body witnesses f5 f6`, so the body always comes before the witness set: `a0` for fund (no redeemer) and `a1 05 81 84 ...` for create and extract.
- The fixed bytes (variant 1's policy id 84967d91..., wallet hash 94bca9c0..., all four reference UTxO ids) hold no a105. So the trigger is per-user and per-run bytes: the user's address, input ids, the fresh datum.
- No test covers index.js.

My test runs the real index.js, filled the way web_server.rs fills index.html, against a fake CIP-30 wallet. When the bytes hold neither pattern, the page submits the correct transaction. When they do, the wallet's witnesses are written into the body and the submitted bytes no longer parse as a transaction, so the node refuses them. No money moves, because the body the wallet signed is never what gets submitted. In a copy outside TREE (since removed) I replaced the search with a positional splice, and the same test passed 5/5.

Severity is low:
- Who reaches it: the user, through an ordinary create, fund or util extract. A stranger could only nudge it by sending a UTxO whose id holds the pattern, and then only if the CLI selects that UTxO.
- What it costs: a signature prompt that leads nowhere and a failed submit with no hint why. Nothing is lost.
- How often: about 1 base address in 573 holds a105 (Monte Carlo, 400k samples). Every create, fund and extract from such an address fails every time; so does extract for a given UTxO and receiving address, because its body is deterministic. Otherwise about 0.3% of runs fail on the fresh datum and about 0.57% on a one-input fund's random bytes.
- The way out: retry when the pattern sits in the fresh datum, or use another -a address.

One correction to the finder's "since": the a105 search came in 52b10c20 (2024-12-06, create only), and the current two-branch form with a0f5f6 in 6efa9d7f (2024-12-09). Both predate 0.2.0. `git diff 0.7.0 HEAD` shows no change to static/, web_server.rs, fund.rs, create.rs or util/extract.rs, so the bug is in the latest CLI tag, 0.7.0, which SECURITY.md puts in scope.

**Fix notes:**

Find the witness set by position and remove both searches (index.js:49-56).

The smallest fix stays in the page:
- Skip the CBOR item after the 0x84 head (the body).
- The next item is the CLI's witness set (`a0` or `a1 05 …`).
- Write `message[0..bodyEnd]`, then a map head for the summed entry counts, then the wallet's entries (sig_part minus its head), then the CLI's entries, then whatever followed (`f5f6`).

That keeps the page's interface, and tests/r51-r4-3.test.ts passes unchanged; I checked this in a copy.

The finder's alternatives also work:
- web_server.rs injects the witness set's offset (decoding with minicbor as build::tx_id does);
- or the page sends the wallet's witnesses back to Rust to merge, which needs a per-run token against cross-site POSTs.

Either changes what the page receives, so this test's fake would need the new injected field, or an answer to that POST.

Same class: the CLI has no other copy of this splice. It is index.js alone, used by create, fund and util extract.

The fix adds no refusal and changes no privacy default, so it needs no call from the owner.

// Chunk 51, r4#3 (the verifier's test). The CLI's signing page,
// seedelf-cli/static/index.js, adds the CIP-30 wallet's witnesses to the
// transaction that `create`, `fund` and `util extract` serve by searching its
// hex for the first "a105" (else the first "a0f5f6"), at any nibble, and
// splicing there. Pallas writes the witness set after the body (`84 body
// witnesses f5 f6`): `a0` when there's no redeemer (fund), `a1 05 …` when there
// is one (create, extract). A body whose hex happens to hold those digits (the
// user's address, an input's id, the fresh datum) gets the witnesses written
// into it, so the page submits a transaction whose body isn't the one the
// wallet signed, and the node refuses it.
//
// This runs the page itself, its two injected blocks filled as web_server.rs
// fills index.html's, against a fake CIP-30 wallet, and reads what it submits.

import { readFileSync } from "node:fs";

import { describe, expect, it } from "vitest";

import { nestsWithin, skip, txId } from "../src/background/cbor";

const cliStatic = (file: string) =>
  readFileSync(new URL(`../../../seedelf-cli/static/${file}`, import.meta.url), "utf8");
const pageScript = cliStatic("index.js");
const pageHtml = cliStatic("index.html");

/** index.html's two injected blocks, filled as web_server.rs fills them (mainnet). */
function serve(message: string): { data: string; network: string } {
  const filled = pageHtml
    .replace('{ "message": "ACAB000000000000" }', `{ "message": ${JSON.stringify(message)} }`)
    .replace('{ "network": "FADECAFE00000000" }', '{ "network": "" }');
  const block = (id: string) => {
    const found = filled.match(new RegExp(`<script id="${id}" type="application/json">([\\s\\S]*?)</script>`));
    if (!found) throw new Error(`index.html has no ${id} block`);
    return found[1]!;
  };
  return { data: block("injected-data"), network: block("injected-network-data") };
}

  href: string;

  children: unknown[];

const element = (text = ""): FakeElement => ({

const WALLET_WITNESSES = `a100${VKEYS}`;

/** Runs the page on `unsigned`, with the wallet picked in the dropdown; returns what it signed and submitted. */
async function signOnThePage(unsigned: string): Promise<{ signed?: string; submitted?: string; status: string }> {
  const served = serve(unsigned);
  const elements: Record<string, FakeElement> = {
    "injected-data": element(served.data),
    "injected-network-data": element(served.network),
    status: element(),
    tx_link: element(),
    tx_cbor: element(),
    wallet_dropdown: element(),
  };
  elements.wallet_dropdown!.value = "cliwallet";
  const seen: { signed?: string; submitted?: string; onLoad?: () => Promise<void> } = {};
  const api = {
    getNetworkId: async () => 1,
    signTx: async (tx: string) => {
      seen.signed = tx;
      return WALLET_WITNESSES;
    },
    submitTx: async (tx: string) => {
      seen.submitted = tx;
      return "ab".repeat(32);
    },
  };
  const cardano = {
    cliwallet: { name: "cliwallet", icon: "data:,", apiVersion: "0.1.0", isEnabled: async () => true, enable: async () => api },
  };
  const document = {
    getElementById: (id: string) => elements[id],
    createElement: () => element(),
    addEventListener: (type: string, listener: () => Promise<void>) => {
      if (type === "DOMContentLoaded") seen.onLoad = listener;
    },
  };
  runInContext(pageScript, createContext({ window: { cardano }, document, setInterval, clearInterval }), {
    filename: "seedelf-cli/static/index.js",
  });
  if (!seen.onLoad) throw new Error("index.js didn't wait for DOMContentLoaded");
  await seen.onLoad();
  return { signed: seen.signed, submitted: seen.submitted, status: elements.status!.textContent };
}

const bytes = (hex: string) => Uint8Array.from(hex.match(/../g) ?? [], (h) => Number.parseInt(h, 16));

/** A transaction's id, body, witness-set entries (key → value) and what follows them; or that it can't be read. */
function read(hex: string) {
  try {
    const b = bytes(hex);
    if (!/^(?:[0-9a-f]{2})+$/.test(hex) || b[0] !== 0x84 || !nestsWithin(b)) return { readable: false };
    const bodyEnd = skip(b, 1, 1);
    const head = b[bodyEnd]!;
    if (head >> 5 !== 5 || (head & 0x1f) >= 24) return { readable: false };
    const witnesses: Record<number, string> = {};
    let at = bodyEnd + 1;
    for (let i = 0; i < (head & 0x1f); i++) {
      const end = skip(b, at + 1, 2);
      witnesses[b[at]!] = hex.slice((at + 1) * 2, end * 2);
      at = end;
    }
    return { readable: true, id: txId(b), body: hex.slice(2, bodyEnd * 2), witnesses, after: hex.slice(at * 2) };
  } catch {
    return { readable: false };
  }
}

/** A CBOR unsigned integer, as minicbor writes it (under 2^32). */
const uint = (n: number) =>
  n < 24
    ? n.toString(16).padStart(2, "0")
    : n < 0x100
      ? `18${n.toString(16).padStart(2, "0")}`
      : n < 0x10000
        ? `19${n.toString(16).padStart(4, "0")}`
        : `1a${n.toString(16).padStart(8, "0")}`;
/** Writes `patch` over `hex` at byte `offset`, keeping its length. */
const put = (hex: string, offset: number, patch: string) =>
  hex.slice(0, offset * 2) + patch + hex.slice(offset * 2 + patch.length);
const input = (id: string, index: number) => `825820${id}${uint(index)}`;

/**
 * `fund -a <address> -s <seedelf> -l 50000000`, as fund.rs builds it: one input,
 * 50 ₳ to the contract under a fresh register, the change back to the address,
 * the fee; no redeemer, so the witness set is empty (`a0`).

function fundTx({ pay = PAY, inputId = INPUT_ID, publicValue = PUBLIC_VALUE } = {}) {
  const datum = `d8799f5830${GENERATOR}5830${publicValue}ff`;
  const toSeedelf = `a300581d71${WALLET_HASH}01${uint(50_000_000)}028201d8185868${datum}`;
  const change = `a2005839${`01${pay}${STAKE}`}01${uint(147_302_511)}`;
  const body = `a300d9010281${input(inputId, 0)}0182${toSeedelf}${change}02${uint(170_605)}`;
  return { unsigned: `84${body}a0f5f6`, body, ours: {} as Record<number, string> };
}

/**
 * `util extract -u <utxo> -a <address>`, as extract.rs builds it: the contract
 * UTxO and one of the address's, everything to the address, collateral and its
 * return, the wallet contract by reference; one spend redeemer (`a1 05 …`).

function extractTx({ pay = PAY } = {}) {

  const body =
    "a7" +
    `00d9010282${input(CONTRACT_UTXO, 0)}${input(USER_UTXO, 1)}` +
    `0181a200${to}01${uint(9_412_337)}` +
    `02${uint(287_442)}` +

    `10a200${to}01${uint(4_568_837)}` +
    `12d9010281${input(WALLET_REFERENCE, 1)}`;
  return { unsigned: `84${body}a105${REDEEMERS}f5f6`, body, ours: { 5: REDEEMERS } as Record<number, string> };
}

/** The page should submit the transaction the CLI built and the wallet signed, with the wallet's witnesses added. */
async function expectSignedAsBuilt(tx: { unsigned: string; body: string; ours: Record<number, string> }) {
  // The fixture is one whole transaction, its body ending where the witness set starts.
  expect(read(tx.unsigned)).toEqual({
    readable: true,
    id: txId(bytes(tx.unsigned)),
    body: tx.body,
    witnesses: tx.ours,
    after: "f5f6",
  });
  const run = await signOnThePage(tx.unsigned);
  expect(run.signed, run.status).toBe(tx.unsigned);
  expect(run.submitted, run.status).toBeDefined();
  expect(read(run.submitted!), `submitted ${run.submitted}`).toEqual({
    readable: true,
    id: txId(bytes(tx.unsigned)), // the body the wallet signed
    body: tx.body,
    witnesses: { 0: VKEYS, ...tx.ours },
    after: "f5f6",
  });
}
