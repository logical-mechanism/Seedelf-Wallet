# r2b#2: verification

From lane R2b, graded low by its finder.

## Trace: confirmed, low

The finding holds. I traced it from the CLI flag to the bail, and a test run on TREE shows it. `utxos::select` makes one pass over the sorted UTxOs. It skips for good any token UTxO that holds none of the tokens being sent, as long as those tokens haven't all been found yet. Take an address whose ADA sits in an unrelated-token UTxO larger than the UTxO holding the token sent, with no ADA-only UTxO big enough to cover the gap. There `select` returns an empty list, and `fund` bails "Not Enough Lovelace/Tokens". The address still holds 51.5 ₳ and the token, and the ledger would take that payment.

I found no guard that saves it:
- Nothing revisits a skipped UTxO.
- The recursion at :295 re-sorts the same list and skips the same UTxO again.
- No existing test covers this layout. utxos_test.rs and selection_integration.rs put the ADA in ADA-only UTxOs or in the holder itself.

Two corrections to the finder's text, neither changes the verdict:
1. The flag is `--asset <pid>.<tkn>=<amt>` (fund.rs:50-57), not `--assets`.
2. It reaches further than "no ADA-only UTxO, or only 5 ₳ ones". It fails whenever the ADA-only UTxOs and the token's holders together fall short of the goal plus the change's minimum. It also hits the plainest use, `fund --asset` with no `--lovelace` (sending an NFT): the test shows that case fails too, with the goal at the token output's minimum (1,616,250 lovelace).

Severity is low, the same as the finder's grade:
- Who: the user, by an ordinary command on a common wallet layout. Most wallets bundle tokens into the main change output, and an NFT usually sits in its own small UTxO.
- Cost: a refused payment with a misleading message. No money is lost, overpaid or locked.
- Way out: from the CIP-30 wallet, send some ADA (not exactly 5 ₳) to your own address so an ADA-only UTxO exists, or move the token into the UTxO holding the ADA, then run fund again. The web wallet is unaffected and can pay the Seedelf.
- Scope: CLI only, in every CLI release including 0.7.0.

**Fix notes:**

The fix is to take every UTxO holding a needed token first, then ADA-only UTxOs, then other token UTxOs, each largest first. That's one sort key in do_select (utxos.rs:202-208): `(!holds_needed, has_tokens, Reverse(lovelace))`. Compute holds_needed once per UTxO rather than in the comparator. It is `build::account_payment`'s order (build.rs:902-914). The existing :238, :248 and :258 branches then already take holders, then ADA, then other token UTxOs for their ADA. I checked this in a throwaway copy: the new test passes, and utxos_test and selection_integration stay green.

The larger option the finder names is moving fund onto core's builders, which would retire `select`. Its only callers are the CLI's create, fund and util extract.

The class:
- I found no other member. Core's other selectors (account_payment, select_script_inputs) take holders first.
- The adjacent item from R4's notes (a token-free 5 ₳ UTxO is never spent by fund, utxos.rs:153) lives in the same pipeline and could be fixed in the same commit if the owner wants.

//! Chunk 51, r2b#2: `utxos::select`, the address-side pick of the CLI's `fund`,
//! passes a token UTxO for good when it holds none of the tokens being sent
//! and they haven't all been found yet. When the address's ADA sits in such a
//! UTxO, sorted ahead of the smaller UTxO holding the token, `select` returns
//! nothing and `fund` bails "Not Enough Lovelace/Tokens", though the address
//! holds the token and ADA enough for the payment and its change.
//!
//! This runs `fund`'s own steps (fund.rs:124-142): `collect_address_utxos`
//! (which drops a pure 5 ₳ UTxO as an assumed collateral), then `select` with
//! the lovelace and tokens asked for.

use seedelf_core::assets::{Asset, Assets};
use seedelf_core::transaction::wallet_minimum_lovelace_with_assets;
use seedelf_core::utxos;
use seedelf_koios::koios::{Asset as KoiosAsset, ProtocolParameters, Ratio, UtxoResponse};

const PID_SENT: &str = "11111111111111111111111111111111111111111111111111111111";
const PID_OTHER: &str = "22222222222222222222222222222222222222222222222222222222";

fn fixture_params() -> ProtocolParameters {
    ProtocolParameters {
        min_fee_a: 44,
        min_fee_b: 155_381,
        coins_per_utxo_size: 4_310,
        key_deposit: 2_000_000,
        drep_deposit: Some(500_000_000),
        price_mem: 0.0577,
        price_step: 0.0000721,
        cost_model_v3: Vec::new(),
        cost_model_v1: Vec::new(),
        cost_model_v2: Vec::new(),
        min_fee_ref_script_cost_per_byte: Ratio::whole(15),
    }
}

fn ada_utxo(byte: u8, lovelace: u64) -> UtxoResponse {
    UtxoResponse {
        tx_hash: hex::encode([byte; 32]),
        value: lovelace.to_string(),
        asset_list: Some(vec![]),
        ..Default::default()
    }
}

fn token_utxo(byte: u8, lovelace: u64, tokens: &[(&str, &str, u64)]) -> UtxoResponse {
    let asset_list: Vec<KoiosAsset> = tokens
        .iter()
        .map(|(pid, name, qty)| KoiosAsset {
            policy_id: (*pid).to_string(),
            asset_name: (*name).to_string(),
            quantity: qty.to_string(),
            ..Default::default()
        })
        .collect();
    UtxoResponse {
        tx_hash: hex::encode([byte; 32]),
        value: lovelace.to_string(),
        asset_list: Some(asset_list),
        ..Default::default()
    }
}

/// `--asset <PID_SENT>.aa=100`
fn sent() -> Assets {
    Assets::new()
        .add(Asset::new(PID_SENT.to_string(), "aa".to_string(), 100).unwrap())
        .unwrap()
}

#[test]
fn r51_r2b_2_fund_takes_ada_from_a_token_utxo_passed_before_the_sent_token() {
    let params = fixture_params();
    // The CIP-30 address: A holds 50 ₳ and 1 of an unrelated token, B holds
    // 1.5 ₳ and the 100 being sent, C is a pure 5 ₳ UTxO (an assumed
    // collateral, so fund leaves it out). 51.5 ₳ and the token are usable.
    let address = vec![
        token_utxo(0x01, 50_000_000, &[(PID_OTHER, "bb", 1)]),
        token_utxo(0x02, 1_500_000, &[(PID_SENT, "aa", 100)]),
        ada_utxo(0x03, 5_000_000),
    ];
    let usable = utxos::collect_address_utxos(address).unwrap();
    assert_eq!(usable.len(), 2, "fund leaves out only the pure 5 ₳ UTxO");

    // `fund --lovelace 10000000 --asset <PID_SENT>.aa=100`
    let ten_ada: u64 = 10_000_000;
    let picked_ten = utxos::select(&params, usable.clone(), ten_ada, sent()).unwrap();
    // `fund --asset <PID_SENT>.aa=100` with no --lovelace: the token output's minimum
    let token_min: u64 = wallet_minimum_lovelace_with_assets(&params, sent()).unwrap();
    let picked_min = utxos::select(&params, usable, token_min, sent()).unwrap();

    assert!(
        !picked_ten.is_empty() && !picked_min.is_empty(),
        "the address holds 51.5 ₳ and the token, yet select picked {} UTxOs for 10 ₳ with the \
         token and {} for the token with its minimum ({token_min} lovelace): an empty pick is \
         fund's \"Not Enough Lovelace/Tokens\"",
        picked_ten.len(),
        picked_min.len(),
    );

    // What select itself promises when it picks: the token, the goal, and a
    // change output at its minimum.
    for (goal, picked) in [(ten_ada, &picked_ten), (token_min, &picked_min)] {
        let (total, found) = utxos::assets_of(picked.clone()).unwrap();
        assert!(found.contains(sent()), "the pick must hold the token sent");
        let change = found.separate(sent()).unwrap();
        let change_min = wallet_minimum_lovelace_with_assets(&params, change).unwrap();
        assert!(
            total >= goal + change_min,
            "picked {total} lovelace, short of the goal {goal} and the change's {change_min}"
        );
    }
}
