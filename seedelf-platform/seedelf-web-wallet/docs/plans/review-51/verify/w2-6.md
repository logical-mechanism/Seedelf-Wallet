## Trace: confirmed, low

Both parts hold as described, and I found no guard, caller or test that stops either.

(a) A site's partial-sign transaction that spends a counterparty's Byron UTxO next to the account's own is refused outright. The ledger would take it with the counterparty's bootstrap witness. owner() reads the found row's text with Address::from_bech32, which only reads bech32, and a Byron address has no bech32 form from any data source. The branch written to count a Byron input as someone else's (cip30.rs:1221-1225) is dead for every source of rows. Private sessions go through the same inspect_tx.

(b) A Byron payee shows as its CBOR in hex ("82d81858…"), both in the sign window's Pays and in Transaction details, where Copy also copies the hex. Pallas's to_bech32 returns Err(InvalidForByron) for Byron. The intent recorded in decode.rs:1395 and rpc.ts:1199 (cede06de) was base58.

The test file holds 3 tests, and all 3 fail on TREE because of the bug. With the finder's fix applied in a copy, all 3 pass.

Grade, low. The site is the one who reaches it. Nothing is lost or misdirected, and the user isn't prompted in (a). In (b) the bytes shown are the real payee, only in a form the user can't check by eye. Both cases are rare: a dApp transaction that spends from or pays a Byron address. There is a way out: the counterparty moves to a Shelley address, or the user signs in another wallet.

**Evidence:**

1. A site calls signTx(tx, true). dapp.ts signTx calls readTx, which calls resolve(…, inputs ∪ collateral) (dapp.ts:2045).
2. The counterparty's UTxO isn't in the view, sent or signed, so it's `missing`. It is fetched with `this.deps.koios(network).utxoInfo(missing)` (dapp.ts:1821). On mainnet that's the data layer first (data-layer.ts:251-252, "Koios's JSON"), else Koios (koios.ts:825-831). 3. `inputs: rows` goes into the request (dapp.ts:2056), then to wasm.inspectDappTx or inspectSessionTx (dapp.ts:2075; lib.rs:6446-6456 runs the same cip30::inspect_tx).
4. KoiosRow.address is a plain String (cip30.rs:48-52), so nothing is checked when it's deserialized.
5. The input loop calls `owner(row)?` (cip30.rs:1261, and 1287 for collateral). owner does `Address::from_bech32(&row.address).map_err(|e| anyhow!("UTxO {}#{} has an unreadable address: {e}", …))?` (cip30.rs:1191). Pallas 0.35.1's from_bech32 is bech32_to_address, bech32 only (lib.rs:617, 427-430), so the whole inspect returns Err.
6. dapp.ts:2081-2082 catches it. The message doesn't start with "The wallet can't read", so the site gets TxSignError.ProofGeneration with that text. Nothing is asked of the user, and the refusal counts toward the site's per-minute limit.
7. The `_ =>` arm at cip30.rs:1221-1225 ("A Byron address needs a bootstrap witness…") never runs:
   - Koios and data-layer rows are text, never bech32 for Byron.
   - Kept own outputs are Shelley.
   - `every` comes from ogmios_utxos, which errors on any Byron output (seedelf-core eval.rs:396-400 `.to_bech32()?`), so dapp.ts outputsOf returns [].
8. If the row were parsed, the arm would put the input in foreign_keys, so others_sign = 1 and complete = false. With partialSign the payment key signs: unknown is empty (cip30.rs:1792) and sign_tx allows it.
9. If the row weren't found at all, the payment key would refuse anyway ("can't find yet", cip30.rs:1792-1801). Neither path lets this transaction be signed.

THE PATH, (b).
1. The outputs loop reads the bytes as Address::Byron, and network_of passes a mainnet Byron address with no magic.
2. `let bech32 = address.to_bech32().unwrap_or_else(|_| address.to_hex());` (cip30.rs:1369) yields hex, because Pallas's Address::to_bech32 is `Address::Byron(_) => Err(Error::InvalidForByron)` (lib.rs:607-612). The same holds in 0.31.0 and 1.4.0, so the comment was never true.

5. Transaction details: decode.rs:1397 has the same fallback, and TxDetail.tsx:749-752 shows and copies `o.address.bech32`.
6. decode.rs:1395-1396's comment ("Pallas writes its base58 for `to_bech32`") and rpc.ts:1199 ("Bech32 (base58 for a Byron address)") both come from cede06de and are wrong. decode.rs:81's doc ("hex for a Byron address") matches the code. Display (lib.rs:693-699) writes base58 for Byron, and FromStr (lib.rs:703-720) reads bech32, then base58, then hex.

//! Chunk 51, finding w2#6: Byron addresses in the dApp connector.
//!
//! (a) Koios's `utxo_info` writes a Byron UTxO's address in base58, as db-sync stores it, and the data layer answers in
//! Koios's JSON; dapp.ts `resolve` hands that row to WebAssembly untouched (`trimmed` keeps `address`). `inspect`'s
//! `owner()` reads a found row's address with `Address::from_bech32`, which reads bech32 only, so a site's
//! partial-sign transaction that spends a counterparty's Byron UTxO beside the account's own is refused whole ("has
//! an unreadable address"), though the ledger takes it with the counterparty's bootstrap witness. The branch meant
//! for it (a Byron input is someone else's, cip30.rs:1221) never runs.
//!
//! (b) A Byron payee is shown as its CBOR in hex, in the sign window's Pays (cip30.rs:1369) and in Transaction
//! details (decode.rs:1397), because Pallas's `to_bech32` is `Err(InvalidForByron)` for Byron. decode.rs's comment
//! and rpc.ts's `TxAddress` both say it's base58, which is what explorers and whoever gave the address write.
//!
//! These assert the right behaviour, so they fail while the bug is there.

use pallas_addresses::Address;
use pallas_addresses::byron::{
    AddrAttrProperty, AddrAttrs, AddrType, AddressPayload, ByronAddress, SpendingData,
};
use pallas_codec::minicbor::bytes::ByteVec;
use pallas_codec::utils::{Bytes, Nullable, Set};
use pallas_crypto::hash::Hash;
use pallas_primitives::{Fragment, TransactionInput, conway};
use seedelf_crypto::cardano::{CardanoAccount, Role};
use seedelf_wasm::cip30::{self, KeyPath, KoiosRow, TxRequest};
use seedelf_wasm::decode::decode_tx;

const PHRASE: &str =
    "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about";
const TX_A: &str = "1111111111111111111111111111111111111111111111111111111111111111";
const TX_B: &str = "2222222222222222222222222222222222222222222222222222222222222222";

fn account() -> CardanoAccount {
    CardanoAccount::from_phrase(PHRASE, 0).unwrap()
}

fn keys() -> Vec<KeyPath> {
    (0..3)
        .flat_map(|index| [KeyPath { role: 0, index }, KeyPath { role: 1, index }])
        .collect()
}

/// The account's own mainnet address, 0/0.
fn ours() -> Address {
    account().base_address(false, Role::Receive, 0).unwrap()
}

/// A counterparty's mainnet Byron address: no network magic, as a Daedalus or Icarus-era wallet's.
fn byron() -> Address {
    let attributes: AddrAttrs = Vec::<AddrAttrProperty>::new().into();
    Address::Byron(ByronAddress::from_decoded(AddressPayload::new(
        AddrType::PubKey,
        SpendingData::PubKey(ByteVec::from(vec![7; 64])),
        attributes,
    )))
}

/// The base58 that Koios, cardano-cli and every explorer write a Byron address in.
fn base58(address: &Address) -> String {
    match address {
        Address::Byron(b) => b.to_base58(),
        _ => unreachable!("a Byron address"),
    }
}

/// A row as `utxo_info` gives it, the address as text.
fn row(tx: &str, index: u64, address: String, lovelace: u64) -> KoiosRow {
    serde_json::from_value(serde_json::json!({
        "tx_hash": tx,
        "tx_index": index,
        "address": address,
        "value": lovelace.to_string(),
        "asset_list": [],
    }))
    .unwrap()
}

fn input(tx: &str, index: u64) -> TransactionInput {
    TransactionInput {
        transaction_id: Hash::new(hex::decode(tx).unwrap().try_into().unwrap()),
        index,
    }
}

fn out(address: &Address, lovelace: u64) -> conway::TransactionOutput {
    conway::PseudoTransactionOutput::PostAlonzo(conway::PostAlonzoTransactionOutput {
        address: Bytes::from(address.to_vec()),
        value: conway::Value::Coin(lovelace),
        datum_option: None,
        script_ref: None,
    })
}

fn tx_hex(inputs: Vec<TransactionInput>, outputs: Vec<conway::TransactionOutput>) -> String {
    let body = conway::TransactionBody {
        inputs: Set::from(inputs),
        outputs,
        fee: 200_000,
        ttl: Some(99_999_999),
        certificates: None,
        withdrawals: None,
        auxiliary_data_hash: None,
        validity_interval_start: None,
        mint: None,
        script_data_hash: None,
        collateral: None,
        required_signers: None,
        network_id: None,
        collateral_return: None,
        total_collateral: None,
        reference_inputs: None,
        voting_procedures: None,
        proposal_procedures: None,
        treasury_value: None,
        donation: None,
    };
    let tx = conway::Tx {
        transaction_body: body,
        transaction_witness_set: conway::WitnessSet {
            vkeywitness: None,
            native_script: None,
            bootstrap_witness: None,
            plutus_v1_script: None,
            plutus_data: None,
            redeemer: None,
            plutus_v2_script: None,
            plutus_v3_script: None,
        },
        success: true,
        auxiliary_data: Nullable::Null,
    };
    hex::encode(tx.encode_fragment().unwrap())
}

fn request(tx: String, inputs: Vec<KoiosRow>, partial_sign: bool) -> TxRequest {
    TxRequest {
        network: "mainnet".into(),
        tx_cbor: tx,
        keys: keys(),
        inputs,
        partial_sign,
        stake_index: 0,
        stake_deposit: None,
        governance: false,
    }
}

#[test]
fn a_counterpartys_byron_input_is_someone_elses_not_an_unreadable_address() {
    let them = byron();
    let text = base58(&them);
    // Pallas reads that text (FromStr: bech32, then base58, then hex) back to the very bytes paid.
    assert_eq!(text.parse::<Address>().unwrap().to_vec(), them.to_vec());

    // A P2P trade: the account's 5 ADA and the counterparty's 10 ADA in, 9.8 ADA to the account, 5 ADA to them.
    let tx = tx_hex(
        vec![input(TX_A, 0), input(TX_B, 0)],
        vec![out(&ours(), 9_800_000), out(&them, 5_000_000)],
    );
    let rows = vec![
        row(TX_A, 0, ours().to_bech32().unwrap(), 5_000_000),
        row(TX_B, 0, text, 10_000_000),
    ];
    let req = request(tx, rows, true);

    let summary = cip30::inspect_tx(&account(), &req)
        .unwrap_or_else(|e| panic!("a found Byron input refused the whole read: {e}"));
    assert!(summary.unknown_inputs.is_empty());
    assert!(
        summary.others_sign >= 1,
        "the Byron input needs its owner's bootstrap witness"
    );
    assert!(!summary.complete);
    assert_eq!(summary.signs, vec!["0/0"]);
    let signed = cip30::sign_tx(&account(), &req)
        .unwrap_or_else(|e| panic!("partialSign was refused: {e}"));
    assert_eq!(signed.summary.signs, vec!["0/0"]);
}

#[test]
fn a_byron_payee_shows_as_its_base58_in_the_sign_window() {
    let them = byron();
    let tx = tx_hex(vec![input(TX_A, 0)], vec![out(&them, 4_800_000)]);
    let rows = vec![row(TX_A, 0, ours().to_bech32().unwrap(), 5_000_000)];
    let summary = cip30::inspect_tx(&account(), &request(tx, rows, false)).unwrap();
    assert_eq!(summary.paid.len(), 1);
    assert_eq!(
        summary.paid[0].address,
        base58(&them),
        "Pays shows the Byron payee as its CBOR hex ({}), not the base58 it was given as",
        them.to_hex()
    );
}

#[test]
fn a_byron_payee_shows_as_its_base58_in_transaction_details() {
    let them = byron();
    let tx = tx_hex(vec![input(TX_A, 0)], vec![out(&them, 4_800_000)]);
    let detail = decode_tx("mainnet", &tx).unwrap();
    let shown = &detail.outputs[0].address;
    assert_eq!(shown.kind, "byron");
    assert_eq!(
        shown.bech32,
        base58(&them),
        "Transaction details shows the Byron payee as its CBOR hex ({}), though decode.rs's comment says base58",
        them.to_hex()
    );
}
