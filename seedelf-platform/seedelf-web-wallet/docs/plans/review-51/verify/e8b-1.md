# e8b#1: verification

From lane E8b, graded low by its finder.

## Trace: confirmed, low

The finding holds on TREE, as the finder describes it, and reaches further than it says. A stranger sends exactly 5 ₳ of ADA alone to the public account's 0/0, carrying a reference script or an inline datum nested past 128 levels. If no collateral is chosen and the account holds no older pure 5 ₳, the wallet takes that UTxO as its collateral by itself ('set by the wallet'). Every Lovejoin build from that public account is then refused in WebAssembly: a mix, mix again, the public-paid way back of a box, and even a Bootstrap, which needs no collateral at all. This is true even when the account holds a 5 ₳ UTxO of its own that is newer than the stranger's.

The Collateral page gives no way out. After Reclaim, its Set takes the page's candidate, which is the same UTxO again, and locking it changes nothing.
- With a measurable script or a deep datum, the only way out is to reclaim and then spend it in a payment (a Send or Make private Max does). Nothing suggests this.
- With a reference script Koios gives no bytes for, no payment can ever spend it, so public-account Lovejoin stays blocked on that account.

The account-paid mint, the launch and a site's getCollateral are unaffected. The mint goes to Ogmios, which takes the collateral as given; the launch says 'The collateral isn't evaluated'.

I found no guard the finder missed, no caller that avoids it, and no test that covers it. It isn't settled or known.

Severity is low, judged on who can reach it, what it costs and the way out:
- Who: a stranger, at 5 ₳ per victim given to the victim, for no gain. It must land while the account has no chosen collateral and no older pure 5 ₳ (a common state for a new wallet).
- Cost: no funds lost and nothing signed. One feature on one account fails, with an error that names the UTxO but not that it's the collateral.
- Way out: mixing from the private balance (sessions use their own collateral) and other public accounts still work. The sub-case of a script Koios gives no bytes for has no way out in the wallet for that account's public Lovejoin, which the owner may weigh as medium.

**Fix notes:**

Fix sketch, checked in a copy:
- Give coin-control.ts:184 collateralFits' rule: `BigInt(u.value) === COLLATERAL_LOVELACE && !u.asset_list?.length && !u.reference_script && !u.inline_datum && !u.datum_hash`. That fixes collateralOf's pick at :205.
- Take collateral()'s candidate (:377) from the raw rows, not UtxoInfo, because asKoios (:464) drops the script and datum. In the sketch: read SESSION_ACCOUNT_UTXOS_PREFIX+network's PathedUtxo rows inside withKeys, keep the outpoints that fit, and filter lists.cardano by them.

The family:
- sessions.ts:1052 collateralFits, wasm lovejoin.rs:348 fits_collateral and lib.rs:985 session_collateral already have the rule. One shared helper keeps the four from drifting.
- Separately, lovejoin.ts:4891 sends the collateral for a Bootstrap, and lovejoin.rs:2356-2360 converts it at depth 0 too. A Bootstrap needs no collateral, so it shouldn't pass or convert one; then a bad collateral can't block it.
- A collateral the user chose that carries a script or datum stays theirs; a site's transaction can use it. The public Lovejoin builds could say plainly that the collateral is the problem, where today they only name the UTxO.

Needs the owner: refusing the row in use() (:391) would refuse a collateral the ledger accepts for a site, which breaks the 2026-10-19 rule. Skipping it in the automatic pick and the candidate refuses nothing: with no candidate, Set pays a fresh 5 ₳ (collateral-build).

To look up, with no network calls made: whether Koios and the data layer give `bytes: null` for a native (timelock) reference script. db-sync's script table keeps bytes only for Plutus scripts, as far as I know. If they do, any stranger can make the no-way-out variant with a tiny native script on 5 ₳.

// Chunk 51, e8b#1: a stranger's 5 ₳ of ADA alone at the public account's 0/0 that carries a reference script, or an
// inline datum nested past core's cbor::MAX_DEPTH (128), passes isCollateralShaped (coin-control.ts:184), which reads
// only the value and the tokens. With no collateral chosen, collateralOf takes it as the oldest pure 5 ₳, and after a
// reclaim it's the Collateral page's candidate, the only UTxO its Set offers. Every Lovejoin build from the public
// account then fails: WebAssembly's Coin::from_row puts the collateral through eval::resolve_row, which refuses both
// shapes. A session's collateral already leaves such a row out (sessions.ts collateralFits, independent review L20).
//
// Each case asserts what the wallet should do, so it fails today and passes once the public account's pick and the
// page's candidate share collateralFits' rule.
import { describe, expect, it } from "vitest";

import { bodyOutpoints } from "../src/background/cbor";
import type { KoiosUtxo } from "../src/background/koios";
import { SESSION_LOVEJOIN_PUBLIC } from "../src/background/lovejoin";
import { account, CHAINS, PASSWORD, publicFunded, type Tested } from "./chain-fixtures";
import { koiosPreprod, testBalances } from "./fakes";
import { ADA } from "./v2-pools";

const STRANGER = "d7".repeat(32);
const OWN_FIVE = `${"e5".repeat(32)}#0`; // publicFunded's own 5 ₳
const hexBytes = (hex: string) => Uint8Array.from(Buffer.from(hex, "hex"));

/** What a stranger can put on an output of 5 ₳ alone: a reference script (one the wallet can measure), or a deep datum. */
const SHAPES: Array<[string, Partial<KoiosUtxo>]> = [
  ["a reference script", { reference_script: { hash: "ab".repeat(28), size: 3, type: "timelock", bytes: "820080" } }],
  ["an inline datum 200 levels deep", { inline_datum: { bytes: `${"81".repeat(200)}00`, value: null } }],
];

/** The stranger's 5 ₳ at the 12-word account's 0/0, a block older than publicFunded's own 5 ₳. */
async function strangers(t: Tested, shape: Partial<KoiosUtxo>): Promise<void> {
  const [first] = Object.values(koiosPreprod.accounts)[0]!.account_utxos.filter((u) => BigInt(u.value) > 1_000_000_000n);
  const keyHash = await t.wallet.withKeys((keys) => keys.cardano.paymentKeyHash(0, 0));
  t.koios.addedToAccounts.push({
    ...first!,
    tx_hash: STRANGER,
    tx_index: 0,
    address: account(12).preprod.receive_0,
    value: "5000000",
    payment_cred: keyHash,
    asset_list: [],
    block_height: first!.block_height! - 1,
    ...shape,
  });
}

describe("r51 e8b#1: a stranger's 5 ₳ the wallet can't put up", CHAINS, () => {
  it.each(SHAPES)("with %s is neither the account's collateral nor the Collateral page's candidate", async (_, shape) => {
    const t = testBalances();
    await t.wallet.create(account(12).phrase, PASSWORD); // no 5 ₳ of its own
    await strangers(t, shape);
    await t.balances.get("preprod");
    // It was read: the account's list holds it.
    expect((await t.coins.lists("preprod")).cardano.some((u) => u.txHash === STRANGER)).toBe(true);

    // The wallet takes none by itself: there's no 5 ₳ a public mix could put up, so Set pays 5 ₳ to 0/0.
    expect(await t.coins.collateral("preprod")).toEqual({ state: "none", reclaimed: false });
    // Nor is it offered after a reclaim, where Set takes the candidate (Collateral.tsx:162-164).
    expect(await t.coins.reclaim("preprod")).toEqual({ state: "none", reclaimed: true });
  });

  it.each(SHAPES)("with %s leaves a public mix the account's own 5 ₳ to put up", async (_, shape) => {
    const t = await publicFunded();
    await strangers(t, shape);
    const mix = await t.lovejoin.publicBuild("preprod", 1, { pool: ADA });
    expect(mix.mixes).toBeGreaterThan(0);
    const kept = await t.wallet.withKeys(() =>
      t.session.get<{ chain: Array<{ kind: string; txCbor: string }> }>(SESSION_LOVEJOIN_PUBLIC),
    );
    for (const tx of kept!.chain.filter((x) => x.kind === "mix")) {
      expect(bodyOutpoints(hexBytes(tx.txCbor), 13)).toEqual([OWN_FIVE]);
    }
  });
});
