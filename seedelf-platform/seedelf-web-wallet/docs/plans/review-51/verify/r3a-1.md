## Trace: confirmed, high

The finding holds end to end, and I found no guard the finder missed. `parse_mix_datum` (seedelf-core/src/lovejoin/mod.rs:387) refuses any constructor that isn't tag 121 with no `any_constructor`. Constructor 0 written as `102([0, [a, b]])` is the same Plutus data: the node's own decoder reads it as `Constr 0 [a, b]` and keeps the bytes as written. Lovejoin's mix_box and mix_logic read only that data, and build the mix's ctx from `serialise_data`, which the node writes in the canonical `d879` form whatever the transaction carries. So anyone who mixes a user's box can write its output datum in the 102 form and the mix passes on chain. Koios and the private index then hand the wallet those bytes unchanged. `PoolBox::from_row` returns None for that row, and every way the wallet finds its boxes goes through `from_row`: wasm `owned_in`, `our_box` (which every withdraw uses, the private-payer one included) and all the draws; the worker's `ownership`, `split`, `splitAll` and `ours`. The box drops out of the user's Lovejoin total, never comes back by itself, can't be brought back, and no Seedelf wallet mixes it again. The money isn't stolen: on chain it is still a well-formed box that only the user's key can withdraw, and a fixed release would find it again. Until then a stranger strands it, for a mix fee of roughly 0.28 to 0.31 ₳ a box, and can do it to every box in every pool. The brief puts that at high ("a stranger can ... strand funds"). The new test fails on TREE because of this line, and passes once the one-line fix is applied in a copy.

```
//! Chunk 51, r3a#1: a mix's outputs are written by whoever builds the mix, and
//! Plutus data spells constructor 0 two ways: the wallet's `121([_ a, b])`, and
//! the general form `102([0, [_ a, b]])`, which the ledger decodes as the same
//! `Constr 0 [a, b]`. mix_logic reads the data, never the spelling, so a
//! stranger's mix of the wallet's box may leave it in the general form. It is
//! still the wallet's box, and the wallet must still see it.

use pallas_codec::minicbor::{self, data::Tag};
use pallas_primitives::Fragment;
use pallas_primitives::conway::PlutusData;
use seedelf_core::lovejoin::{PoolBox, Protocol, mix_datum};
use seedelf_crypto::register::Register;
use seedelf_crypto::schnorr::random_scalar;
use seedelf_koios::koios::{UtxoResponse, register_of_datum};
use serde_json::json;

/// `d8 66 82 00 9f 58 30 <a> 58 30 <b> ff`: constructor 0 under tag 102.
fn general_form(a: &[u8; 48], b: &[u8; 48]) -> Vec<u8> {
    let mut e = minicbor::Encoder::new(Vec::new());
    e.tag(Tag::new(102))
        .and_then(|e| e.array(2))
        .and_then(|e| e.u8(0))
        .and_then(|e| e.begin_array())
        .and_then(|e| e.bytes(a))
        .and_then(|e| e.bytes(b))
        .and_then(|e| e.end())
        .unwrap();
    e.into_writer()
}

/// A pool row as Koios (or the private index, through `utxoOf`) lists one:
/// exactly the box value at `mix_box`, with this inline datum's bytes.
fn box_row(protocol: &Protocol, datum: &[u8]) -> UtxoResponse {
    serde_json::from_value(json!({
        "tx_hash": hex::encode([0x51; 32]), "tx_index": 0,
        "address": protocol.mix_box_address().to_bech32().unwrap(),
        "value": protocol.denom.to_string(), "stake_address": null,
        "payment_cred": hex::encode(protocol.mix_box_hash), "epoch_no": 0,
        "block_height": 0, "block_time": 0, "datum_hash": null,
        "inline_datum": { "bytes": hex::encode(datum), "value": null },
        "reference_script": null, "asset_list": [], "is_spent": false,
    }))
    .unwrap()
}

#[test]
fn a_box_another_mixer_wrote_in_constructor_0s_general_form_is_still_the_wallets() {
    let sk = random_scalar();
    // A box of the wallet's after a mix: a re-randomized register, b = sk·a.
    let moved = Register::create(sk).unwrap().rerandomize().unwrap();
    let a: [u8; 48] = hex::decode(&moved.generator).unwrap().try_into().unwrap();
    let b: [u8; 48] = hex::decode(&moved.public_value).unwrap().try_into().unwrap();
    let canonical = mix_datum(&a, &b);
    let general = general_form(&a, &b);
    assert_eq!(hex::encode(&canonical[..3]), "d8799f");
    assert_eq!(hex::encode(&general[..5]), "d86682009f");

    // The same Plutus data, read either way: Constr 0 [a, b].
    let data = |cbor: &[u8]| PlutusData::decode_fragment(cbor).unwrap();
    assert_eq!(data(&general), data(&canonical));
    // The Seedelf register reader already takes this spelling (launch review H4).
    let register = register_of_datum(&general).expect("a register in the general form");
    assert_eq!(
        (register.generator, register.public_value),
        (moved.generator.clone(), moved.public_value.clone())
    );

    for network_flag in [true, false] {
        let protocol = Protocol::of(network_flag).unwrap();
        // The wallet's own spelling: found, and the wallet's.
        let ours = PoolBox::from_row(&box_row(&protocol, &canonical), &protocol)
            .expect("the canonical box is a box");
        assert!(ours.is_owned(&sk));
        // The same box in the general spelling, as a stranger's mix may leave it.
        let respelled = PoolBox::from_row(&box_row(&protocol, &general), &protocol);
        assert!(
            respelled.as_ref().is_some_and(|b| b.is_owned(&sk)),
            "network_flag {network_flag}: the wallet's box, {} ₳ at mix_box with datum \
             Constr 0 [a, b] spelled 102([0, [_ a, b]]), isn't read as a box at all \
             (PoolBox::from_row = {respelled:?}), so owned, our_box and every withdraw \
             and mix leave it out",
            protocol.denom / 1_000_000
        );
        let respelled = respelled.unwrap();
        assert_eq!((respelled.a, respelled.b), (a, b));
    }
}
```

## Impact: confirmed, high

The impact holds at high. I tried to refute each step and none failed.

Who can do it, and at what cost. Anyone can mix. Lovejoin v2's Mix branch takes no proof from a box's owner: the mixer picks the re-randomizers, so it needs two or more well-formed boxes and nothing else. The wallet relies on this too: it draws other people's boxes into its own mixes. The mixer writes every output's bytes. The contract reads each output's datum as abstract Data and hashes serialise_data's canonical form. A tag-102 spelling therefore changes neither the checks nor the proofs. The ledger accepts the spelling: Conway's CDDL takes #6.102([uint, ...]) with any index. It also keeps the datum's original bytes, and honest sources (Koios, the data layer's rows) pass them through untouched. Cost: a 3-box mix measured about 0.82 ₳ on mainnet, so about 0.28 ₳ a box. Collateral comes back, and the mixer gains nothing.

What the user loses. parse_mix_datum refuses tag 102, so from_row drops the row. Every way the wallet finds a box goes through from_row: owned_in, our_box (which every withdraw uses) and the worker's ownership. The worker's header says: "Boxes aren't remembered, they're found." So Bring one back, Bring every box back, the scheduled return, a restore and other devices all fail to find it. The CLI has no Lovejoin code. Waiting doesn't help either: Lovejoin's own SDK also requires tag 121 (identify.ts:65), so no honest mixer will ever draw the box and rewrite its datum.

Is there a way out? Not today. The money isn't taken: mix_box and the Owner branch read Data, so only the user's key can withdraw the box. A release whose reader accepts tag 102 brings every box back on every device with no on-chain step.

Narrower than it reads, but not below high:
- The stranger can't tell which boxes are a user's, so they hit boxes blindly. Exposure is what sits in pools at the time: a return's leaves during their 1 to 6 h wait, boxes a Bootstrap holds, a cut chain's boxes, and boxes left in the retired classic pool. It never reaches the private balance or the public account.
- The floor side effect is the documented fallback. Re-tagged boxes leave `others`, which is what the 30-box floor counts. A campaign therefore trips the floor, and returns then come back directly with the floor warning (backlog.md:84; launch review M5). That is no further harm, and it limits how much new money flows into a pool under attack.

Grade. The brief's table puts "a stranger can strand funds" at high. Past reviews graded the same pattern high, though code could recover the money each time: the launch review's H4 (a stranger's 1 to 2 ₳ UTxO at mix_box: "no Seedelf Wallet can find or withdraw its boxes") and the independent review's H1 and H2 (a stranger strands a session's money for 10 to 50 ₳).
