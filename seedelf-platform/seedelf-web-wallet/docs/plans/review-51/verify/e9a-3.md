# e9a#3: verification

From lane E9a, graded low by its finder.

## Trace: confirmed, low

The finding holds as described. I traced it from where the input enters (a stranger pays the account's 0/0 payment key under their own stake key, or under none) to the outcome (UTxO details call that address "Your receive address, the one Receive shows."). I found no guard on the way.

The account is read by payment key, whatever the stake part. account.ts uses credential_utxos and matches payment_cred to the walked keys, and the walk always includes index 0. The data layer mirrors Koios's credential_utxos, so mainnet behaves the same. The worker gives each account UTxO only `path: {role, index}`, the payment key's place, plus the raw address. The details pick the note from path alone: role 1 gives change, index 0 gives receive, anything else gives other. Nothing compares the address with Receive's address, which is receiveAddress(net, 0), base(0/0, 2/0).

The wallet's own reading elsewhere says the opposite. The connector's warning for this exact shape reads "dappUi.warn.ownKey": "It pays your payment key with a stake part that isn't yours ... its staking rewards aren't yours."

The test shows it through the worker's own list, then the real render. The UTxO at the true Receive address passes as a control. Both the stranger-staked UTxO and the enterprise UTxO under 0/0 get the receive note, so the test fails on TREE. A minimal fix in a throwaway copy makes the same test pass: the worker marks UTxOs that carry the account's own stake key (carriesStakeKey), and the details say "the one Receive shows" only for those.

Grade: low, as the finder graded it. Who: a stranger sets up the state, paying about 1 ₳ plus a fee, and the ₳ goes to the user. An enterprise UTxO can also come from the user's other wallet. The cost lands only if the user then copies the address from UTxO details rather than from Receive, and uses it to receive. Payments to it stay the user's: they are spendable, counted and spent. Only the staking rewards and the vote's weight on that ADA go to the stranger's stake key, or to nobody for an enterprise address. That is a small cost in an edge case.

There is a way out. account_send's change goes to base(0/0, 2/0) (wasm lib.rs:1696), so the next payment that spends such a UTxO puts its leftover back under the account's stake key. Paying one's own Receive address does the same.

Not excluded by SECURITY.md: it needs no dishonest data source, since the stranger's row sits inside an honest answer, and no social engineering, since the false claim is the wallet's own. Not settled anywhere I searched.

The aside about '.other' and '.change' holds only in a weaker form. Those notes say "of yours" (true by payment key) and "used by another wallet with your recovery phrase", which is false when a stranger built the address. But they don't name an address the user would take for Receive's. My test pins only the receive note.

// Chunk 51, finding e9a#3 (lane E9a), its trace verifier's test. A UTxO under the public account's receive key 0/0
// at an address whose staking part isn't the account's own (a stranger's stake key, or none at all) is the
// account's money: account.ts reads by payment key, so the worker lists it with 0/0's path. Its details must not
// call that address "Your receive address, the one Receive shows": Receive shows the base address with the
// account's own stake key 2/0, and a payment to the other one is staked with the stranger's key, or with none.
// The control: a UTxO at the Receive address itself still says so.
import { createElement } from "react";
import { renderToStaticMarkup } from "react-dom/server";
import { describe, expect, it } from "vitest";

import type { KoiosUtxo } from "../src/background/koios";
import type { UtxoInfo } from "../src/shared/rpc";
import { UtxoDetails } from "../src/ui/screens/Utxos";
import { preprodAddress } from "./fixtures/bech32";
import { koiosPreprod, loadTestWasm, testBalances, vectors } from "./fakes";

const PASSWORD = "correct horse battery";
const v = vectors("cardano_account.json").find((x) => x.account === 0 && x.phrase.split(" ").length === 12)!;
const RECEIVE = "Your receive address, the one Receive shows.";
const noop = () => undefined;

/** The note under a public UTxO's address, as its details render it. */
const whose = (utxo: UtxoInfo) =>
  renderToStaticMarkup(createElement(UtxoDetails, { of: "cardano", utxo, busy: false, onLock: noop, onClose: noop })).match(
    /data-testid="utxo-address-whose">([^<]*)</,
  )?.[1];

describe("r51 e9a#3: whose a public UTxO's address is", () => {
  it("calls only the Receive address itself the one Receive shows, not 0/0 under another staking part", async () => {
    const t = testBalances();
    await t.wallet.create(v.phrase, PASSWORD);
    const key = loadTestWasm().CardanoAccount.fromPhrase(v.phrase, 0).paymentKeyHash(0, 0);
    const recorded = koiosPreprod.accounts[v.preprod.stake]!.account_utxos;
    // Koios rows like the recorded ones, at addresses a stranger can pay: as balances.test.ts builds them.
    const stray = (n: string, address: string, value: string): KoiosUtxo => ({
      ...recorded[0]!,
      tx_hash: n.repeat(64),
      tx_index: 0,
      address,
      value,
      payment_cred: key,
      stake_address: null,
      asset_list: [],
    });
    // The account's 0/0 with a stranger's stake key (any 28 bytes), and 0/0 with no staking part.
    const strangers = preprodAddress(key, "ab".repeat(28));
    const enterprise = preprodAddress(key);
    t.koios.addedToAccounts.push(stray("e", strangers, "30000000"), stray("f", enterprise, "40000000"));

    await t.balances.get("preprod");
    const { receiveAddress } = await t.wallet.account("preprod");
    const listed = (await t.coins.lists("preprod")).cardano;
    const at = (address: string) => listed.find((u) => u.address === address)!;

    // The scenario: the worker lists both as 0/0's, the same place as the Receive address ...
    expect(receiveAddress).toBe(v.preprod.receive_0);
    expect(at(receiveAddress).path).toEqual({ role: 0, index: 0 });
    expect(at(strangers).path).toEqual({ role: 0, index: 0 });
    expect(at(enterprise).path).toEqual({ role: 0, index: 0 });
    // ... and the stranger's one starts as the Receive address does, as far as the details' 16…8 shows its head.
    expect(strangers).not.toBe(receiveAddress);
    expect(strangers.slice(0, 16)).toBe(receiveAddress.slice(0, 16));

    // The control: a UTxO at the Receive address itself is said to be it.
    expect(whose(at(receiveAddress))).toBe(RECEIVE);
    // The finding: neither of the others is the one Receive shows (soft, so each is reported).
    expect.soft(whose(at(strangers)), "0/0 under a stranger's stake key").not.toBe(RECEIVE);
    expect.soft(whose(at(enterprise)), "0/0 with no staking part").not.toBe(RECEIVE);
  });
});
