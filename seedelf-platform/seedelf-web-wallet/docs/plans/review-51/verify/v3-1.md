# v3#1: verification

From lane V3, graded low by its finder.

## Trace: confirmed, low

The finding holds as described. The pinned Lake (v4.24.0) writes a module's .trace only after its build returns, and nothing ever removes the old one. So a rebuild that fails, times out or is killed keeps the last good build's trace, still newer than the module's unchanged source. tally.py:68 and count.py:81 test freshness only against the module's own source, so both read that old log as ok and count its old ✅.

I reproduced it with byte-identical copies of TREE's check.sh, Audit/run-all.sh, Audit/count.py and tally.py, on a two-package Lake project in scratch. After a dependency change broke the module:
- check.sh's summary said FAILED for it and for its importer;
- Audit/logs/count.txt said "2 ok";
- tally.py said "2 Valid, 0 not ok";
- both traces were byte-for-byte the first build's.

The control shows the docstrings' assumption (a failed build shows as NO TRACE) holds only on a first build.

Three corrections to the finding:
- Under run-all.sh the FAILED is also saved, in Audit/logs/<family>.log, which count.txt then contradicts.
- TIMEOUT and KILLED rebuilds go the same way (traced from the code, not run).
- I count 658 traced modules, not 655. The 140 Audit modules and the 0 proof modules match.

Grade: low, and I agree with the finder.
- **Who:** nobody. Only the proofs' own tooling is affected, after a re-pin, a toolchain change or an import change that breaks a module. No wallet user, stranger or site can reach it.
- **Cost:** a ✅ count or audit verdict taken from these two tools could include modules that no longer build.
- **Way out:** check.sh's summary, its exit status and the family log still give the true result.
- **Today:** no published count rests on such a trace, and no proof module's trace is older than an import's.

**Evidence:**

Trace, every file opened in TREE (seedelf-verification unchanged since cd764fba):

1. **The pinned Lake.** lean-toolchain pins leanprover/lean4:v4.24.0, and `lake --version` gives "Lake version 5.0.0-src+797c613 (Lean version 4.24.0)".
2. **Lake writes the trace only after a build returns.** ~/.elan/toolchains/leanprover--lean4---v4.24.0/src/lean/lake/Lake/Build/Common.lean, `buildAction`: `let outputs ← build -- fatal errors will abort here` / `let log := (← getLog).takeFrom iniPos` / `writeBuildTrace traceFile depTrace outputs log`. Its `finally` only adds the build time. The docstring says the trace is saved "if the build completes without a fatal error (i.e., it does not `throw`)".
3. **The module build path.** Lake/Build/Module.lean:630-642: `Module.buildLean … := buildAction depTrace mod.traceFile do … compileLeanModule … mod.clearOutputHashes; mod.computeOutputHashes`. In recBuildLean (:673-679), `readTraceFile mod.traceFile` then `replayIfUpToDate`, and `unless upToDate do discard <| mod.buildLean …`. Nothing removes mod.traceFile.
4. **A failed compile throws.** Lake/Build/Actions.lean:27-77, compileLeanModule, only creates directories, writes the setup file and runs lean. Then `if out.exitCode ≠ 0 then error s!"Lean exited with code …"` throws, so writeBuildTrace never runs. check.sh's `timeout "$1" lake build` (LIMIT) or the scope's OOM kill (CAP) stops lake before that point too.
5. **tally.py's only freshness test.** tally.py:59-68: `trace = os.path.join(root, ".lake", "build", "lib", "lean", rel + ".trace")` … `("built before its source changed", os.path.getmtime(trace) < os.path.getmtime(src))`. Its docstring (:11) says "Lake writes no trace for a failed build."
6. **count.py's freshness test.** count.py:79-82: `NO TRACE` when the trace is missing, `STALE` when `getmtime(trace) < getmtime(src)`. Otherwise it reads the old log and returns "ok" (:99). Its docstring (:15) makes the same assumption. Its main() never exits non-zero.
7. **The audit's runner.** run-all.sh:29: `CAP=$cap LIMIT=$limit ./check.sh "$f" 2>&1 | tee "Audit/logs/$f.log"`, with no pipefail, and the loop goes on. Then :33 `python3 -I Audit/count.py 2>&1 | tee Audit/logs/count.txt`.

The nearest recorded items are different mechanisms:
- **script-hex-not-lake-inputs** (open; chunk 49 step 1): Lake doesn't track the .hex files, so nothing rebuilds.
- **checksh-cannot-tell-replay**: check.sh's ok can't tell a valid replay from a build.

None records a last good trace surviving a failed rebuild and being read as ok. Chunk 46 mentions count.py only for blasterProven's rename (:46). The README documents check.sh's exit status and summary, and never mentions tally.py.

**Fix notes:**

Fix the class: two readers copy the same freshness rule, tally.py:68 and count.py:81, behind one runner (check.sh), plus run-all.sh's verdict file.

**Preferred, option (a).** In check.sh, when a module's rc isn't 0 (FAILED, TIMEOUT 124, KILLED 137), delete that module's .trace together with its .olean, .ilean and .c under .lake/build. Then the readers see NO TRACE, as both docstrings assume, and Lake must rebuild next time. Deleting the trace alone isn't enough: with the trace missing, Lake falls back to comparing the old outputs' mtimes (Common.lean `.missing => depTrace.checkAgainstTime info`; Config/Module.lean:205-222 reads the olean, ilean and c). That fallback can take the old olean as up to date, and check.sh would then print ok with nothing proved.

**Option (c) works too.** check.sh writes each run's verdict per module, and both readers refuse a module whose last verdict wasn't ok.

**Option (b) is weaker** (the readers also compare against imports' traces and lakefile.lean, lake-manifest.json and lean-toolchain). It misses a path-required dependency's change, the #77 test worktree's setup ("Both of its lakefiles require that PlutusCoreBlaster by path"). Nothing in the package's lakefile, manifest or toolchain changes, and the dependency's traces sit in another package's .lake.

**Also:**
- Correct both docstrings (tally.py:11, count.py:15): a failed first build leaves no trace, but a failed rebuild keeps the last good one.
- Have run-all.sh carry each family's check.sh status into count.txt, or at least use `set -o pipefail` per family. count.py itself always exits 0.

**Timing.** Land this before, or with, chunk 49 step 1. Its *Done means* ("Root must fail" after a .hex swap) is exactly a failed rebuild over an old good trace, so read it from check.sh's summary.

#!/usr/bin/env bash
# r51 v3#1: a module whose rebuild fails keeps its last good build's Lake trace, and
# seedelf-verification's tally.py and Audit/count.py (and so Audit/run-all.sh's count.txt) read
# that old trace as ok.
#
# Builds a two-package Lake project outside TREE, on TREE's pinned Lean (v4.24.0), with
# byte-identical copies of TREE's check.sh, Audit/run-all.sh, Audit/count.py and tally.py. dep
# stands in for a pinned tool (PlutusCoreBlaster), and demo for the proofs.
# 1. dep v1: build demo through run-all.sh (check.sh's scopes, then count.py): both modules ok.
# 2. dep v2 makes Dep.answer @[irreducible], as #77's instByteViewString broke cek_rfl: re-run.
#    check.sh says FAILED for both. Asserts that count.txt and tally.py don't call them ok.
# 3. Control: the same failure on a first build (no older trace) shows as NO TRACE.
# Exits 1 while the bug is there (the assertions in step 2 fail), 0 once it's fixed.
#   systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0 timeout 20m bash r51_v3_1_repro.sh
set -u
TREE=/home/logic/Documents/LogicalMechanism/Seedelf-Wallet-chunk51/seedelf-verification
HERE=$(cd "$(dirname "$0")" && pwd)
PKG=$HERE/r51_v3_1_pkg
export PATH=/usr/bin:/bin:$HOME/.elan/bin
rm -rf "$PKG"
mkdir -p "$PKG/dep/Dep" "$PKG/demo/Demo" "$PKG/demo/Audit"
TOOLCHAIN=$(cat "$TREE/lean-toolchain")

# --- dep: the "tool" package. Tac.lean defines a `blaster` tactic that logs Blaster's line
# ("✅ Valid") only when its goal is proved, as Blaster does; Base.lean is what the re-pin changes.
echo "$TOOLCHAIN" > "$PKG/dep/lean-toolchain"
cat > "$PKG/dep/lakefile.lean" <<'EOF'
import Lake
open Lake DSL

package dep

lean_lib Dep
EOF
cat > "$PKG/dep/Dep/Tac.lean" <<'EOF'
import Lean
open Lean Elab Tactic in
elab "blaster" : tactic => do
  evalTactic (← `(tactic| decide))
  logInfo "✅ Valid"
EOF
echo 'def Dep.answer : Nat := 42' > "$PKG/dep/Dep/Base.lean"

# --- demo: the "proofs" package, with TREE's tools copied in unchanged.
echo "$TOOLCHAIN" > "$PKG/demo/lean-toolchain"
cat > "$PKG/demo/lakefile.lean" <<'EOF'
import Lake
open Lake DSL

package demo

require dep from "../dep"

@[default_target] lean_lib Demo
EOF
cat > "$PKG/demo/Demo/Top.lean" <<'EOF'
import Dep.Tac
import Dep.Base

theorem Demo.answer_eq : Dep.answer = 42 := by blaster
EOF
cat > "$PKG/demo/Demo/Down.lean" <<'EOF'
import Demo.Top

theorem Demo.answer_eq' : Dep.answer + 0 = 42 := by blaster
EOF
printf 'Demo.Top\nDemo.Down\n' > "$PKG/demo/Audit/audit-quick.txt"
cp "$TREE/check.sh" "$PKG/demo/check.sh"
cp "$TREE/tally.py" "$PKG/demo/tally.py"
cp "$TREE/Audit/count.py" "$PKG/demo/Audit/count.py"
cp "$TREE/Audit/run-all.sh" "$PKG/demo/Audit/run-all.sh"
for f in check.sh tally.py Audit/count.py Audit/run-all.sh; do
  cmp -s "$TREE/$f" "$PKG/demo/$f" || { echo "copy of $f differs from TREE's"; exit 2; }
  echo "same as TREE: $f $(sha256sum < "$PKG/demo/$f" | cut -c1-16)"
done

cd "$PKG/demo" || exit 2
T=.lake/build/lib/lean/Demo
run_audit() {  # the audit's own flow: check.sh's capped scopes per module, then count.py
  bash Audit/run-all.sh audit-quick > "run-$1.out" 2>&1
  echo "-- check.sh's summary (Audit/logs/audit-quick.log):"
  sed -n '/^== summary/,$p' Audit/logs/audit-quick.log
  echo "-- Audit/logs/count.txt:"
  cat Audit/logs/count.txt
  echo "-- python3 -I tally.py Demo:"
  python3 -I tally.py Demo | tee "tally-$1.out"
}
traces() { for m in Top Down; do
  [ -f "$T/$m.trace" ] && echo "$m.trace $(stat -c '%y' "$T/$m.trace") sha256 $(sha256sum < "$T/$m.trace" | cut -c1-16)" \
    || echo "$m.trace: none"; done; }

echo; echo "===== 1. dep v1: the first build"
run_audit 1
traces | tee traces-1.out

echo; echo "===== 2. dep v2 (Dep.answer @[irreducible], the re-pin); demo's own files untouched"
sleep 1
echo '@[irreducible] def Dep.answer : Nat := 42' > "$PKG/dep/Dep/Base.lean"
run_audit 2
traces | tee traces-2.out
echo "-- the failed build's own error (run-2.out):"
grep -m2 -E '^error: ' run-2.out
echo "-- what Top's kept trace logs (level, message):"
python3 -I -c 'import json,sys; [print(" ", e.get("level"), e.get("message","").splitlines()[0][:90]) for e in json.load(open(sys.argv[1]))["log"] if e.get("level")!="trace"]' "$T/Top.trace"

fail=0
echo; echo "===== assertions after the failed rebuild"
if grep -q '^FAILED    Demo.Top' Audit/logs/audit-quick.log; then echo "ok   control: check.sh's summary says FAILED Demo.Top"
else echo "??   control: check.sh didn't fail Demo.Top, so this run shows nothing"; exit 2; fi
if cmp -s traces-1.out traces-2.out; then echo "info both traces are byte-for-byte the first build's: Lake kept them"; fi
if grep -qE '^  ok +Demo.Top:' Audit/logs/count.txt; then echo "FAIL count.txt calls Demo.Top ok, though its build just failed"; fail=1
else echo "ok   count.txt doesn't call Demo.Top ok"; fi
if grep -qE '^  ok +Demo.Down:' Audit/logs/count.txt; then echo "FAIL count.txt calls Demo.Down ok, though it can't build behind Demo.Top"; fail=1
else echo "ok   count.txt doesn't call Demo.Down ok"; fi
if grep -q '^NOT OK   Demo.Top' tally-2.out; then echo "ok   tally.py lists Demo.Top as NOT OK"
else echo "FAIL tally.py lists Demo.Top as ok and counts its old ✅: $(tail -1 tally-2.out)"; fail=1; fi

echo; echo "===== 3. control: the same failure on a first build (no older trace)"
rm -rf .lake/build Audit/logs
run_audit 3
traces

echo
[ $fail = 0 ] && echo "PASS: a failed rebuild doesn't read as ok" || echo "BUG REPRODUCED: a failed rebuild reads as ok"
exit $fail
