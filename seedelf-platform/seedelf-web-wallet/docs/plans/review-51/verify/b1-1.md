## Trace: confirmed, low

The finding holds, and it reaches more locales than the five it names. third-party.mjs:225 sorts each group of the notices with `a.name.localeCompare(b.name)` and passes no locale, so the order comes from the default ICU locale of the Node process that runs `npm run package`. That locale is read from LC_ALL, then LC_MESSAGES, then LANG. Nothing on the path pins it: not the package.json script, package.mjs, third-party.mjs, vite.config.ts, build.sh or npm. package.mjs:55-56 writes that text into dist/licenses/THIRD-PARTY.txt, and :116-120 zip every file in dist/. A different notices file therefore gives a different zip and a different SHA-256 from the one releases.md records. Yet releases.md's "Checking a package" and README.md:121 tell anyone to rebuild and compare, and they name only clang and Node as unpinned. The owner's second build runs "in the same terminal" (development.md:290-296), so it shares the locale and agrees. I found no guard, no test and no settled item that covers it.

My test runs TREE's own thirdParty() in a fresh Node per locale. It fails 7 of 8 cases today; the en_US case is the control and passes. With only line 225 changed to `localeCompare(b.name, "en-US")`, in a copy outside TREE, all 8 pass.

The finder named cs, sk, et, lt and lv. Sorting the 141 real crate names under all 123 ICU 78.3 collation locales, 23 locales in 19 languages reorder them: az, br, cs, cy, dsb, ee, et, fy, ha, haw, hsb, ig, lt, lv, om, sk, sq, th, uz. Thai ignores punctuation, so it reorders the npm group too.

- **Who:** user. That is anyone who follows releases.md's check from a shell whose LANG, LC_MESSAGES or LC_ALL is one of those locales; LANG alone is enough, and no glibc locale needs to be installed.
- **Cost:** a false "this package isn't what its commit builds", which undermines the reproducibility claim the README makes. No money, key or privacy is at stake, and the uploaded zips are fine.
- **Way out:** rebuilding under LC_ALL=C or en_US gives the recorded order, but no doc says so. Diffing the two zips would show that only THIRD-PARTY.txt's line order differs.

That is the brief's low: a small cost in an edge case.

**Fix notes:**

**Fix.** third-party.mjs:225 becomes `components.sort((a, b) => a.name.localeCompare(b.name, "en-US"))`. A code-unit sort would also work, but it would reorder the notices once (for example `_` against `-`); "en-US" keeps the same order. The owner's shell here is LANG=en_US.UTF-8, and C resolves to en-US too; the test's en_US case matched C's text. So every recorded zip from 1.0.0 to 1.9.1 stays reproducible on the fixed code. This is a caveat: I didn't open a shipped zip's notices, because the only ones are in the main checkout. The fixed copy passed this test 8 of 8. No refusal and no screen change: needs_owner false.

**For the owner.** The fix can't reach the tags already pushed. releases.md's "What's pinned, and what isn't" should say that 1.0.0 to 1.9.1 build their recorded bytes only in an en-US or C locale, for example `LC_ALL=C.UTF-8 npm run package`, and that the shell's LANG or LC_MESSAGES changes the notices' order. The wording is the owner's.

**The same family.** tokens.mjs:101 (`a.localeCompare(b)` over the registry's hex units, where da and nb's "aa" contraction reorders them) and dreps.mjs:121's tie-break (`ia.localeCompare(ib)`) also take the default locale. Both write committed JSON, which a checker builds from, so they don't break reproducibility. They only reorder a refresh's diff if it's run from such a locale. Give them "en-US" in the same change.

**Wider than the finding says.** It names cs, sk, et, lt and lv. In ICU 78.3 it is 19 languages: az, br, cs, cy, dsb, ee, et, fy, ha, haw, hsb, ig, lt, lv, om, sk, sq, th and uz. LANG alone is enough, and LC_COLLATE alone isn't.

**About the test.** It runs `cargo tree` and `cargo metadata` read-only and offline, and needs the crates' sources already fetched. It takes about 4 s. A fixer adopting it for CI may drop CARGO_NET_OFFLINE.

```
// Chunk 51, b1#1. licenses/THIRD-PARTY.txt is one of the store zip's files:
// scripts/package.mjs writes thirdParty()'s text into dist/ and zips every file
// there, and releases.md says the same commit gives the same zip. So the notices
// must be the same text whatever locale the packaging shell has. third-party.mjs
// sorts each group with localeCompare and no locale, which takes the shell's
// (LC_ALL, then LC_MESSAGES, then LANG). Each case runs thirdParty() in a fresh
// node with that locale, as `npm run package` would, and compares it with C's.
// Each run asks cargo for the module's crates, offline (CARGO_NET_OFFLINE).

import { execFileSync } from "node:child_process";
import { createHash } from "node:crypto";
import { fileURLToPath, pathToFileURL } from "node:url";

import { beforeAll, describe, expect, it } from "vitest";

const extension = fileURLToPath(new URL("..", import.meta.url));
const script = pathToFileURL(fileURLToPath(new URL("../scripts/third-party.mjs", import.meta.url))).href;

/** thirdParty("1.9.1").text, from a fresh node whose locale is `locale`. */
function noticesIn(locale: string): string {
  const env: NodeJS.ProcessEnv = { ...process.env, LC_ALL: locale, CARGO_NET_OFFLINE: "true", RUSTUP_AUTO_INSTALL: "0" };
  delete env.NODE_OPTIONS;
  const code = `import { thirdParty } from ${JSON.stringify(script)}; process.stdout.write(thirdParty("1.9.1").text);`;
  return execFileSync(process.execPath, ["--input-type=module", "-e", code], {
    cwd: extension,
    env,
    encoding: "utf8",
    maxBuffer: 64 << 20,
    timeout: 180_000,
  });
}

/** The notices' component lists: everything before the licence texts. */
const listing = (text: string) => text.slice(0, text.indexOf("Licence texts")).split("\n");
const sha256 = (text: string) => createHash("sha256").update(text).digest("hex");

describe("the store zip's third-party notices", () => {
  let reference = "";
  beforeAll(() => {
    reference = noticesIn("C");
  }, 180_000);

  it.each(["en_US.UTF-8", "et_EE.UTF-8", "lt_LT.UTF-8", "lv_LV.UTF-8", "cs_CZ.UTF-8", "sk_SK.UTF-8", "cy_GB.UTF-8", "th_TH.UTF-8"])(
    "are the same text in %s as in C",
    (locale) => {
      const text = noticesIn(locale);
      expect(listing(text)).toEqual(listing(reference));
      expect(sha256(text)).toBe(sha256(reference));
    },
    180_000,
  );
});
```
