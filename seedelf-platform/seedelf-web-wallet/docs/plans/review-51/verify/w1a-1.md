# w1a#1: verification

From lane W1a, graded low by its finder.

## Trace: confirmed, low

The finding holds as described. Max to one Seedelf skips the one-transaction try and goes straight to `max_in_parts`. Nothing there checks that the named tokens are in `request.utxos`. When it's asked for more of a token than those UTxOs hold, the parts send the holders' share. The next part then has no holder left, so `more` stays true, `at_most` is 0 and the picks are empty. `fit_part` then fails with a plain anyhow error rather than core's `NotEnough`. So `is_short` is false, no chain is tried and the leftovers are blamed on tokens (`LeftWhy::Tokens`). With none of the token there, Max is refused as "Not enough ADA".

The input is reachable from the UI. The Send form's token max is `unlocked(balances.seedelf)`, which still counts UTxOs that a chain being sent has reserved. `readContract` drops those from `utxos`. Such a chain is a session return that merges into the funding change (the swap runner sends these in the background) or a payment's parts still to go. Send is gated only by `watching`, which lasts 10 minutes after a submission Home tracks. transfer.ts's own `leftOut` handling of `returning` UTxOs shows the code expects Max to be built in this state.

I found no guard the finder missed. Amounts are safe: core's `holding` runs first in `select_script_inputs` and refuses in plain words, so the shortfall's `most()` never gets over-held tokens. The withdraw side isn't reachable today. Make public's Everything ignores named tokens, and `most` runs only after a shortfall error.

Grade: low. The user reaches it with an ordinary action, but only in an edge state. No money is lost or misdirected, because the review shows what's built. The harm is that Max leaves the ADA-only UTxOs behind with a false reason, or is refused with a false "Not enough ADA". There is a way out: wait for the chain to land, drop or lower the token, or run Max again.

Not known: none of the searched lists covers it (see known_ref).

**Fix notes:**

There are three things to fix, in Rust and in TS.

1. The refusal, in `build_transfer_parts`' Max path (lib.rs:4633). One line, `build::max_inputs(&request.utxos, &assets_of(&only.tokens)?, usize::MAX)?;`, restores one transaction's refusal in core's words, and the test passes with it (checked in a copy). A dedicated check would match CLAUDE.md's overflow rule better: `assets_of` over `only.tokens` (it also refuses zero, malformed and duplicate entries, which `share_of` and `less` drop or double-count today), then a u128 total per token over `request.utxos`. The other option, sending what's held and saying so, changes what Max offers.

2. `fit_part`'s empty-pick bail (lib.rs:4062-4064). It shouldn't be read as `LeftWhy::Tokens`: give it its own error, and keep Tokens for `too_much` and `fitting`.

3. The TS half. The private Send form offers reserved tokens. `unlocked` (format.ts:376) could subtract reserved UTxOs as it subtracts locks, or the form could say they're held by a chain being sent. Either changes what a screen offers.

The finder's "both Max paths" overstates the withdraw side. `build_withdraw_parts`' `most` (lib.rs:4764) isn't reachable with over-held tokens today: Make public's Everything ignores named tokens (lib.rs:4775-4779), and `most` runs only after a shortfall error from the amount path, which core's `holding` refuses first (build.rs:2558). A check there would be defensive only.

//! Chunk 51, w1a#1: Max in parts (`build_transfer_parts`, a single payment with `lovelace` null) goes straight to
//! `max_in_parts`, which never checks that the tokens it's asked to send are in the UTxOs it's given. The Send
//! form offers a token's whole held figure (`unlocked(balances.seedelf)`), which counts UTxOs a chain being sent
//! has reserved; `readContract` leaves those out of `utxos`. Asked for more of a token than `utxos` hold, a part
//! with no holder left picks nothing and `fit_part` bails with a plain "Not enough ADA" (not core's `NotEnough`),
//! which `max_in_parts` reads as a part that failed for its tokens: the UTxOs of ADA alone stay, blamed on a token

/// UTxO `n`: `lovelace` more than the least its `tokens` need in one output (api_test's `parts_of_any_shape`).
fn utxo(n: u64, lovelace: u64, tokens: &[TokenAmount]) -> UtxoResponse {
    let pp = ProtocolParameters::from_koios(&params()).unwrap();
    let held = tokens.iter().fold(Assets::new(), |all, t| {
        all.add(
            Asset::new(
                t.policy_id.clone(),
                t.asset_name.clone(),
                t.quantity.parse().unwrap(),
            )
            .unwrap(),
        )
        .unwrap()
    });
    let least = wallet_minimum_lovelace_with_assets(&pp, held).unwrap();
    UtxoResponse {
        tx_hash: format!("{n:064x}"),
        value: (least + lovelace).to_string(),
        asset_list: Some(
            tokens
                .iter()
                .map(|t| Held {
                    decimals: 0,
                    quantity: t.quantity.clone(),
                    policy_id: t.policy_id.clone(),
                    asset_name: t.asset_name.clone(),
                    fingerprint: String::new(),
                })
                .collect(),
        ),
        ..base()
    }
}

/// Token T, `quantity` of it.
fn t(quantity: u64) -> TokenAmount {
    TokenAmount {
        policy_id: format!("{:056x}", 0xabc0_0000u64),
        asset_name: format!("{:064x}", 0x1000u64),
        quantity: quantity.to_string(),
    }
}

fn ada(first: u64, n: u64, lovelace: u64) -> Vec<UtxoResponse> {
    (first..first + n).map(|i| utxo(i, lovelace, &[])).collect()
}

/// What's wrong with Max in parts over `utxos`, asked for 15 T: `None` when it's refused in words naming the
/// token, or built with every UTxO of ADA alone spent.
fn wrong(case: &str, sk: blstrs::Scalar, utxos: &[UtxoResponse]) -> Option<String> {
    let policy = t(0).policy_id;
    match api::build_transfer_parts(sk, transfer(utxos.to_vec(), vec![t(15)])) {
        Err(e) => {
            let e = e.to_string();
            (e.contains("Not enough ADA") || !e.contains(&policy))
                .then(|| format!("{case}: Max in parts refused as {e:?}, though {} UTxOs of ADA alone are there", utxos.len()))
        }
        Ok(parts) => {
            let spent: Vec<&api::OutRef> = parts.iter().flat_map(|p| &p.inputs).collect();
            let ada_left: Vec<&UtxoResponse> = utxos
                .iter()
                .filter(|u| u.asset_list.iter().flatten().next().is_none())
                .filter(|u| {
                    !spent
                        .iter()
                        .any(|i| i.tx_hash == u.tx_hash && i.tx_index == u.tx_index)
                })
                .collect();
            if ada_left.is_empty() {
                return None;
            }
            let last = parts.last().unwrap();
            let paid: u64 = parts
                .iter()
                .map(|p| p.payments[0].lovelace.parse::<u64>().unwrap())
                .sum();
            let tokens: Vec<String> = parts
                .iter()
                .flat_map(|p| p.payments[0].tokens.iter().map(|x| x.quantity.clone()))
                .collect();
            let stranded: u64 = ada_left.iter().map(|u| u.value.parse::<u64>().unwrap()).sum();
            Some(format!(
                "{case}: Max in parts went as {} part(s) paying {paid} lovelace and T {tokens:?}, and left {} UTxOs \
                 of ADA alone ({stranded} lovelace) unspent; the last part says left = {}, left_why = {:?}",
                parts.len(),
                ada_left.len(),
                last.left,
                last.left_why,
            ))
        }
    }
}

#[test]
fn max_in_parts_asked_for_more_of_a_token_than_its_utxos_hold_is_refused_for_the_token_or_spends_the_ada() {
    let sk = seedelf_key_v1(PHRASE, 0).unwrap();
    let mut problems = Vec::new();

    // A: 10 T spendable (5 more held by a chain being sent, so the form offers 15), and 25 UTxOs of 10 ₳ alone.
    let mut some = vec![utxo(1, 1_000_000, &[t(10)])];
    some.extend(ada(100, 25, 10_000_000));
    // One transaction's Max refuses it in words, through core's `holding`.
    let one = api::build_transfer(sk, transfer(some.clone(), vec![t(15)]))
        .err()
        .map(|e| e.to_string())
        .unwrap_or_default();
    assert!(one.contains("holds only 10 of the token"), "one transaction's Max: {one:?}");
    problems.extend(wrong("A (10 of 15 T spendable)", sk, &some));

    // B: none of T spendable (all of it held by a chain being sent), and the same 25 UTxOs of ADA alone.
    let none = ada(100, 25, 10_000_000);
    let one = api::build_transfer(sk, transfer(none.clone(), vec![t(15)]))
        .err()
        .map(|e| e.to_string())
        .unwrap_or_default();
    assert!(one.contains("doesn't hold the token"), "one transaction's Max: {one:?}");
    problems.extend(wrong("B (no T spendable)", sk, &none));

    assert!(problems.is_empty(), "\n{}", problems.join("\n"));
}
