# e2b#1: verification

## Trace: confirmed, low

It holds, and I ran it. The traced files are byte-identical to web-wallet/1.9.1.

chainSoFar counts a mix as finished once its chain's return (`chain.last`) is sent, so `started` comes back false. A session closes only once its account reads empty, so a stranger's UTxO that lands between the chain's build and the close keeps it open, and the runner calls bringBack. buildBack then takes the Lovejoin branch again, because throughLovejoin is true for every mix:
- **With a stranger's 5 ₳ of ADA alone plus spare ADA:** a second chain is built and sent with the mix's own box count and pool. I ran it on a deposit mix. On a Mix my boxes again session the same branch re-mixes the wallet's own boxes; that part is traced, not run.
- **With no 5 ₳ there (2 ₳, or 1 ₳ that can't even come back):** collateralWanted returns true for any mix that isn't deposit-only. buildBack writes `mix.skipped` = NO_COLLATERAL before it builds the return. The closed mix, whose boxes did go in and were mixed, then reads "Not mixed" / "Came back without going into Lovejoin" / "Lovejoin was left out: …". On a Bootstrap the same branch writes mixCannotPay instead (traced).

No guard stops it:
- markCut skips a chain whose last transaction was sent.
- The close needs an empty account.
- The only test, return-chain-scope.test.ts:154, has a stopped chain.

The code contradicts its own record. The L17 fix's commit title (c421bd29) is "a mix never starts a second chain", and chainSoFar's comment gives a reason that fits a finished mix just as well. But `!record?.mix` only guards the "rest came back directly" case.

One detail is overstated. The finder says nothing holds the boxes from Lovejoin's withdraws meanwhile. In fact, once the second chain is recorded, lovejoin.ts's chainsMixing holds every withdraw, and fanOut reserves the chain's inputs as soon as it's built.

The finder's "since" also needs a correction. The rule dates from ed7c01b0 (chunk 16, a finished chain lets later returns through Lovejoin) and c421bd29 (L17). aaf2e068 only moved it into chainSoFar. It's in every tag from web-wallet/1.6.0 to 1.9.1.

Severity is low:
- Only a stranger can reach it, by paying the one-time account inside the chain's sending window. That costs about 1.2 ₳ for the label, or 5 ₳ plus mix fees for a second chain, and the money comes back to the user.
- The harm is false status words on a finished mix, or an unasked chain with a fresh wait for its boxes.
- Nothing is lost or stuck, and the boxes still come back by themselves.

**Fix notes:**

**The fix.** End a mix's Lovejoin once a chain of it went in, finished or stopped. Don't do it by making `started` true for a finished mix: buildBack would then mark the finished chain CHAIN_CUT at 4535 (the hub would say it stopped) and call tailChain at 4580. Use a flag of its own. The copy's minimal fix passes the test: chainSoFar returns `done: !!record?.mix && finished && wentIn`, and line 4616 becomes `if (!direct && !started && !done && ...)`. lovejoinWantsCollateral (4967) and intoPool (4565) should read the same flag, so no 5 ₳ offer and no collateral mix go to a finished mix's later arrival.

**`mix.skipped`.** Write it only for the mix's own return, before any chain of it went in, never from a later return; the write at 4687-4691 sits before the build. Same class as e2b#2's `received` and `lovejoinSkipped`, which a later return overwrites.

**Needs the owner.** architecture.md:735's general rule ("One that finished ... doesn't hold a later return of the same session back from Lovejoin") lets a finished mix's later arrival go through Lovejoin, while L17's title says a mix never starts a second chain. The owner picks; then architecture.md:735 should name the finished case, and return-chain-scope.test.ts gets this file's first case.

**A rarer way in, traced partway and not run.** In chainSoFar, the `t.txHash === chain.last` half of `finished` has no `!t.replaced`. So a chain's return that Koios took but that never lands (marked replaced at act 3736-3739) still counts as finished. Its rebuilt return would take the Lovejoin branch with the session's own leftover change, and could write mixCannotPay with no stranger involved.

// Chunk 51, e2b#1: a mix from the Lovejoin tile whose whole chain went (its deposit, its mix and its return, all on
// chain), paid by a stranger before the runner closes it: the account's address is public from the funding, and a
// session closes only once nothing at it can come back (act). What reaches it then is the stranger's, not the mix's.
// It comes back directly, never in a second chain over the mix's own settings (independent review L17, c421bd29: "a
// mix never starts a second chain"), and the mix still reads as mixed: `mix.skipped`, which the Lovejoin hub shows as
// "Not mixed", says why the mix's own boxes never went in, never why a stranger's later 2 ₳ didn't. The finished twin
// of return-chain-scope.test.ts's "a mix whose chain stopped partway". The real WebAssembly, Lovejoin v2's 5 ₳ pool
// (v2-pools.ts), and fakes of Koios.
import { describe, expect, it } from "vitest";

import type { KoiosUtxo } from "../src/background/koios";
import { detailOf, subOf } from "../src/ui/screens/Lovejoin";
import { account, AGREES, atSession, PASSWORD, sessionsOf } from "./chain-fixtures";
import { testBalances } from "./fakes";
import { ADA, ADA_POOL, ADA_ROWS } from "./v2-pools";

/** Building a chain runs the scripts of every mix in it. */
const CHAINS = { timeout: 120_000 };
const FUNDING = "ab".repeat(32);
/** The mix's return, its chain's last. */
const LAST = "ae".repeat(32);

type Book = { sessions: Array<{ chain: { last: string }; txs: Array<{ kind: string }>; mix: { skipped?: string } }> };

/**
 * Mix session 0 into the 5 ₳ pool whose chain finished: its funding, deposit, mix and return, all on chain, as pump
 * leaves it. `paid`: what a stranger paid its account since.
 */
async function finished(paid: KoiosUtxo[]) {
  const t = testBalances({ pools: [ADA_POOL] });
  await t.wallet.create(account(12).phrase, PASSWORD);
  t.koios.evaluation = AGREES;
  const at = t.clock.now;
  const done = (kind: string, txHash: string) => ({ kind, txHash, at, confirmed: true });
  await t.store.set("sessions.preprod", {
    next: 1,
    sessions: [
      {
        index: 0,
        ownStake: true,
        createdAt: at,
        txs: [done("out", FUNDING), done("deposit", "ac".repeat(32)), done("mix", "ad".repeat(32)), done("back", LAST)],
        mix: { boxes: 1, pool: ADA },
        auto: { approved: { minAmountOut: "0", fund: { lovelace: "15000000", tokens: [] } } },
        chain: { total: 3, last: LAST, at },
      },
    ],
  });
  t.koios.addedToAccounts.push(...paid, ...ADA_ROWS);
  // One wave deep, and its collateral's mix off, as the stopped twin has it: the return asked about is the one that
  // brings back what's at the account.
  await t.deps.preferences.set({ lovejoinDepth: 1, lovejoinCollateral: false });
  return { t, sessions: sessionsOf(t) };
}

describe("a mix whose chain finished, paid by a stranger before it closes (chunk 51, e2b#1)", () => {
  it("brings what reaches its account after back directly, never in another chain", CHAINS, async () => {
    // 40 ₳, and 5 ₳ of ADA alone a chain can put up as its collateral.
    const { t, sessions } = await finished([atSession("c1".repeat(32), 0, "40000000"), atSession("c2".repeat(32), 1, "5000000")]);
    await sessions.advance("preprod", 0, true);
    const book = (await t.store.get<Book>("sessions.preprod"))!;
    expect(book.sessions[0]!.txs.map((x) => x.kind)).toEqual(["out", "deposit", "mix", "back", "back"]);
    expect(book.sessions[0]!.chain.last).toBe(LAST);
    expect(t.koios.submitted).toHaveLength(1);
  });

  it("still reads as mixed once a stranger's 2 ₳ came back and it closed", CHAINS, async () => {
    const stranger = atSession("c3".repeat(32), 0, "2000000");
    const { t, sessions } = await finished([stranger]);
    // The runner brings the 2 ₳ back, directly: no 5 ₳ at the account for a chain's collateral.
    await sessions.advance("preprod", 0, true);
    expect(t.koios.submitted).toHaveLength(1);
    // It lands, spending the 2 ₳, and the next step closes the session.
    t.koios.addedToAccounts.splice(t.koios.addedToAccounts.indexOf(stranger), 1);
    t.koios.confirmations = 1;
    t.clock.now += 60_000;
    await sessions.advance("preprod", 0, true);
    const [view] = await sessions.list("preprod");
    expect(view!.stage).toBe("closed");
    // Its boxes went in and were mixed: Done on the hub, never "Not mixed" (Lovejoin.tsx tagOf reads `mix.skipped`),
    // and its row says so, with no reason it was left out.
    expect({ skipped: view!.mix?.skipped, sub: subOf(view!, t.clock.now), detail: detailOf(view!) }).toEqual({
      skipped: undefined,
      sub: expect.stringMatching(/^In Lovejoin since /),
      detail: undefined,
    });
  });

  it("still reads as mixed when a stranger's 1 ₳ that can't come back is left at its account", CHAINS, async () => {
    const { t, sessions } = await finished([atSession("c4".repeat(32), 0, "1000000")]);
    // Too little to pay its own way back: nothing is sent, it's left behind, and the next step closes the session.
    await sessions.advance("preprod", 0, true);
    expect(t.koios.submitted).toHaveLength(0);
    t.clock.now += 60_000;
    await sessions.advance("preprod", 0, true);
    const [view] = await sessions.list("preprod");
    expect(view!.stage).toBe("closed");
    expect({ skipped: view!.mix?.skipped, sub: subOf(view!, t.clock.now) }).toEqual({
      skipped: undefined,
      sub: expect.stringMatching(/^In Lovejoin since /),
    });
  });
});
