## Trace: confirmed, low

The finding holds as described. The connect window's private-session form reads `call("balances", {})` itself and stores `b.seedelf` raw. The worker's `seedelf.lovelace` and `tokens` count every spendable owned UTxO, the locked ones included, and report the locks apart in `locked`. The form states its line, caps the amount and offers tokens against that raw side. It never calls `unlocked()` and never says what is locked. The funding's build (privateBuild → siteOutBuild → buildFunding → readContract → coins.seedelf) leaves locked UTxOs out.

A test with the real worker and real WebAssembly shows the whole case. With 100 ₳ held and 60 ₳ plus a token locked:
- the form says "100 ₳ in your private balance";
- with 50 typed it shows no "more than" note, and Review stays on;
- it offers the token.
The build then refuses 50 ₳ ("Not enough ADA in your private balance for this, its fee and the change."), refuses the token, and builds 30 ₳.

Every other form gets Home's `free` side (`unlocked`), and chunk 12's design says the forms offer only what's unlocked. Nothing settles this: it isn't in the backlog, in any archived review's Not fixed list, in the plans or in SECURITY.md.

One detail differs from the scenario. The token's build fails in core's own untranslated English, "The Seedelf balance doesn't hold the token <policy hex>.<name hex>", not in the same "Not enough ADA…" words.

Grade: low, as the finder had it. Only the user reaches it, by locking private UTxOs (a deliberate, uncommon action) and then funding a private session. Nothing is signed or lost: the build refuses before Send. The way out is to lower the amount, unlock on the UTxOs screen, or Decline. The cost is a refusal whose words contradict the figure just shown and never name the lock.

// (`call("balances")`) and states and caps the amount against all of it, what the user locked included, where Home
// hands every other form the unlocked side (`unlocked`) and the funding's build leaves locked UTxOs out (coin-control.ts

const seam = vi.hoisted(() => {
  /** A thenable that answers at once: an effect's `.then` lands in the same render. */
  interface Answer {
    then(ok?: ((value: unknown) => unknown) | null, no?: ((error: unknown) => unknown) | null): Answer;
  }
  const answered = (value: unknown): Answer => ({ then: (ok) => (ok ? answered(ok(value)) : answered(value)) });
  const pending: Answer = { then: () => pending };
  const state = {
    /** The components whose own effects run, by name. */
    effects: new Set<string>(),
    answers: new Map<string, unknown>(),
    asked: [] as string[],
    /** A useState seeded: the call right after a run of calls starting as `after`, itself starting as `initial`. */
    seeds: [] as Array<{ after: unknown[]; initial: unknown; value: unknown; used?: true }>,
    initials: [] as unknown[],
    call(type: string): Answer {
      state.asked.push(type);
      return state.answers.has(type) ? answered(state.answers.get(type)) : pending;
    },
    seeded(initial: unknown): unknown {
      const before = state.initials;
      state.initials = [...before, initial];
      for (const seed of state.seeds) {
        if (seed.used || before.length < seed.after.length || !Object.is(initial, seed.initial)) continue;
        const run = before.slice(before.length - seed.after.length);
        if (!seed.after.every((want, i) => Object.is(run[i], want))) continue;
        seed.used = true;
        return seed.value;
      }
      return initial;
    },
  };
  return state;
});

  /** The named components' effects, run during the render, again only when a dependency changes. */
  function seamEffect(run: () => void | (() => void), deps?: readonly unknown[]) {
    const last = react.useRef<readonly unknown[] | null>(null);
    const cleanup = react.useRef<void | (() => void)>(undefined);

    cleanup.current?.();
    cleanup.current = run();
  }
  return {
    ...react,
    useEffect: seamEffect,
    useLayoutEffect: seamEffect,
    useState: (initial?: unknown) => react.useState(seam.seeded(initial)),
  };
