# x4#2: verification

From lane X4, graded low by its finder.

## Trace: confirmed, low

The sessions runner reads the unlock's wait once, in waits(), before a step's Minswap and Koios calls, and never again before it signs and submits. If the user locks and unlocks while those calls are out, the step is signed and sent under the new unlock, seconds after it. Privacy review §3.1, independent review L10-L12, architecture.md:643 and runs.ts:35-36 promise that doesn't happen. My test shows the swap order submitted right after the unlock. Lovejoin's withdraw refuses the same shape (lovejoin.ts:7644). The cost is a timing hint in a narrow race: no money moves wrongly, and nothing gets stuck.

**Evidence:**

The doc comment on waits() (:3931-3935) claims it covers "a run under way across a lock", but only for steps that reach waits() after the unlock.

The race is narrow, as the finder's scenario implies. The whole lock and unlock must fall inside one network wait that has no wallet call in it:
- W1, from waits() to inspect's withKeys: Minswap's estimate and build-tx (up to 20 s each), plus Koios utxo_info for a direct swap.
- W2, from inspect's accounts() to signAndSend's withKeys: cancelsChecked's Koios reads (45 s timeout, plus a 429 hold of up to 60 s).
If the wallet is still locked at the next wallet call, the step throws WalletLocked, its retry write fails while locked, runAll's catch swallows it, and nothing is sent.

Correction to the scenario: isEnabled doesn't show the unlock (dapp.ts:28-30: it says "connected" whether locked or not). A connected site sees the unlock when its reads start being answered again (privacy.md:337).

**Fix notes:**

Sketch I tested, in a copy only:
1. In waits(), when it lets a step go, store `run === "asked" ? undefined : unlocked`.
2. In go(), clear it in a finally.
3. At the top of signAndSend, `if (stored !== undefined && (await wallet.unlockedAt()) !== stored) throw new Error(...)`.
The step then retries in 30 s, and the next run's waits() draws the fresh wait, because createdAt < unlocked and now - unlocked < 20 min. With it, r51-x4-2 passes and unlock-waits.test.ts passes 17/17. The sketch uses a field, which works only because the sessions queue runs one step at a time.

For the real fix:
- Pass the unlock that waits() read through go() to the send as an argument, not a field.
- Re-check `wallet.unlockedAt()` after the last network wait and before anything is recorded, at three places:
  - the top of signAndSend, for the order and the cancel;
  - sendBack before refuseParts/sendRecorded, for a direct return;
  - sendChain before its first update and recordChain, for a return through Lovejoin, whose first send is in pump.
- On a change, prefer recording the new unlock's draw (unlockWait and unlockDrawn, as waits() sets them) and returning quietly. A throw also works, but the page shows a retry reason for 30 s.
- 'asked' runs (Try now, Stop, Refresh) stay exempt, as waits() makes them.

Same class as x4#1: Lovejoin's quiet rule is also read only before its network waits. needs_owner: no. The fix enforces the existing default (privacy review §3.1) and adds no refusal of anything the user asks for. The comment at runs.ts:35-36 becomes true once it's in.

Severity is low:
- Who: the user, locking and unlocking within one step's network wait: seconds for Minswap, up to a minute under a Koios 429 hold. A site can't lock the wallet. An auto-lock followed by an unlock inside that same wait is rarer still.
- Cost: a session's order, cancel or return's first transaction lands seconds after the unlock. A connected site whose reads just started being answered again can line that up. Koios sees the session's submits from the same IP anyway (privacy.md:235).
- Nothing is lost or stuck, so no way out is needed.

// Chunk 51, x4#2: a swap's step that the unlock's wait let go (sessions.ts waits) before a lock and an unlock,
// both inside its Minswap call, is never sent seconds after that unlock: nothing goes out the moment the wallet
// unlocks (privacy review §3.1, independent review L10-L12). Lovejoin's withdraw refuses the same shape
// (lovejoin.ts lockedWhileBuilding; lovejoin-withdraw-submit.test.ts, "a withdraw built across a lock and an
// unlock"). The harness is unlock-waits.test.ts's "a swap's step at the unlock": the real WebAssembly, and fakes
// of Koios, giveme.my and Minswap.
import { describe, expect, it } from "vitest";

import { Collateral } from "../src/background/collateral";
import type { KoiosUtxo } from "../src/background/koios";
import { UNLOCK_WAIT_MS } from "../src/background/lovejoin";
import { Minswap } from "../src/background/minswap";
import { SessionService } from "../src/background/sessions";
import { SESSION_UNLOCKED_AT } from "../src/background/wallet";
import { txIdOf } from "./fixtures/cbor";
import { bytes, swapTx } from "./fixtures/swap-tx";
import { busyFor, loadTestWasm, minswapEstimate, sessionSwap, testBalances, vectors, withdrawPreprod } from "./fakes";
import { ADA_ROWS } from "./v2-pools";

const PASSWORD = "correct horse battery";
const PHRASE = vectors("cardano_account.json").find((v) => v.account === 0 && v.phrase.split(" ").length === 12)!.phrase;
const SLOW = { timeout: 30_000 };
const SWAP = swapTx();
const SWAP_TX = txIdOf(bytes(SWAP));

type T = ReturnType<typeof testBalances>;

async function unlocked() {
  const t = testBalances();
  await t.wallet.create(PHRASE, PASSWORD);
  // One spend: the funding takes the 25 ₳ UTxO alone.
  const evaluation = withdrawPreprod.amount.evaluation as { result: unknown[] };
  t.koios.evaluation = { ...evaluation, result: evaluation.result.slice(0, 1) };
  return t;
}

/** The session service with giveme.my's witness and the one-time key's signature stood in for. */
function signing(t: T) {
  const wasm = loadTestWasm();
  t.collateral.answer = { status: 200, body: { witness: "a1008182" } };
  t.minswap.swapCbor = SWAP;
  return new SessionService({
    ...t.deps,
    wasm: {
      ...wasm,
      signScriptSpend: (_key: unknown, request: string) => {
        const { txCbor } = JSON.parse(request) as { txCbor: string };
        return JSON.stringify({ txCbor, txHash: txIdOf(Uint8Array.from(Buffer.from(txCbor, "hex"))) });
      },
    } as typeof wasm,
    collateral: () => new Collateral("https://www.giveme.my/preprod/collateral/", t.collateral.fetch),
    store: t.store,
    minswap: () => new Minswap("https://aggr.monorepo-testnet-preprod.minswap.org/aggregator", t.minswap.fetch),
    alarm: { start: async () => undefined },
  });
}

/** Session 0's funding sent, and landed: Koios confirms it, and the account holds what the recorded swap spends. */
async function funded(t: T, sessions: SessionService) {
  const out = await sessions.outBuild("preprod", await sessions.quote("preprod", minswapEstimate.ask));
  await sessions.outSubmit("preprod", out.txHash);
  t.koios.confirmations = 1;
  t.koios.addedToAccounts.push({
    ...ADA_ROWS[0]!,
    tx_hash: sessionSwap.utxo.tx_hash,
    tx_index: sessionSwap.utxo.tx_index,
    address: sessionSwap.address,
    value: sessionSwap.utxo.value,
    payment_cred: sessionSwap.keyHash,
    inline_datum: null,
    asset_list: [],
  } as KoiosUtxo);
}

const waitsUntil = async (sessions: SessionService) => (await sessions.list("preprod"))[0]!.auto!.waitsUntil;

describe("r51 x4#2: a swap's step under way across a lock and an unlock", SLOW, () => {
  it("isn't sent seconds after the unlock: it waits the new unlock's fresh draw, then goes", async () => {
    const t = await unlocked();
    const sessions = signing(t);
    await funded(t, sessions);
    // Long into the unlock: the order is due, and no unlock's wait holds it back (waits says go).
    await busyFor(t, UNLOCK_WAIT_MS[1] + 60_000);
    const sent = t.koios.submitted.length;
    const sentSince = () => t.koios.submitted.slice(sent).map((b) => txIdOf(b));
    // The alarm's run reaches the order. While Minswap builds it, the user locks and unlocks again.
    const minswap = t.minswap.fetch;
    let unlockedAt: number | undefined;
    t.minswap.fetch = async (url, init) => {
      if (url.includes("build-tx") && unlockedAt === undefined) {
        await t.wallet.lock();
        t.clock.now += 20_000;
        await t.wallet.unlock(PASSWORD);
        unlockedAt = t.clock.now;
      }
      return minswap(url, init);
    };
    await sessions.runAll("preprod");
    t.minswap.fetch = minswap;
    expect(unlockedAt).toBeDefined();
    expect(await t.wallet.withKeys(() => t.session.get(SESSION_UNLOCKED_AT))).toBe(unlockedAt);
    // Nothing goes out at the moment of the unlock: not the order, nor anything else.
    expect(sentSince()).not.toContain(SWAP_TX);
    expect(sentSince()).toEqual([]);
    // The alarm's next run, a minute on: still nothing, and the step waits a fresh draw from that unlock.
    await busyFor(t, 60_000);
    await sessions.runAll("preprod");
    expect(sentSince()).toEqual([]);
    const until = (await waitsUntil(sessions))!;
    expect(until).toBeGreaterThanOrEqual(unlockedAt! + UNLOCK_WAIT_MS[0]);
    // Once it's past, the order goes: the step is held, never dropped.
    await busyFor(t, until - t.clock.now);
    await sessions.runAll("preprod");
    expect(sentSince()).toEqual([SWAP_TX]);
  });
});
