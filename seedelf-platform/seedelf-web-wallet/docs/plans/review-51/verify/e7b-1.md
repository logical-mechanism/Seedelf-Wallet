## Trace: confirmed, low

The finding holds. When Koios's account_info names the pool or vote the user picks, the worker refuses the build: staking.ts:539-544 throws samePool / sameDrep. Both screens stop it before that. Pools.tsx:354 and 366-370 put the label "You're staking with this pool" where the Stake button goes. Voting.tsx:128, 135-138 and 195 grey Review with "Your voting power already goes there".

Nothing below the worker refuses it. wasm's stake() (lib.rs:1888-1925) and core's Staking::of (staking.rs:235-243) build a StakeDelegation or VoteDeleg for any registered key. Conway's DELEG has no rule against a delegatee the key already holds, so the ledger takes it as a no-op that costs only the fee. The brief's owner rule (2026-10-19) says the wallet doesn't refuse that; a warning at most. The refusal is older than the rule (756a646e, 2026-09-24) and no record settles it.

The 1.2.0 release review (C35, 4279db80) already removed the sibling guard in core's own-DRep registration (`if *delegate && !drep_state.own_vote` became `if *delegate`), because "a DRep that isn't registered holds no delegations, so that's stale … Delegating again to it is valid". These are the copies that remain.

My test fails on TREE at exactly these lines. It passes in a copy with them removed.

The cost is narrower than the finding says, in two ways:
1. It needs the data source to name a delegation the ledger no longer holds: a pool retired and re-registered under the same ID, or a DRep retired under protocol 10 and registered again. Whether Koios's or the data layer's account_info does this is chain data I couldn't check offline (look it up in backlog O6's live DRep retirement; Koios may already drop delegations to retired pools). The code's own C35 comment treats the DRep case as real. The case of a server a block behind is transient: a retry a block later goes through, at no cost.
2. "Possibly an epoch of rewards" is overstated. Going through another pool and straight back in the same epoch loses nothing, because the snapshot takes the last delegation.

Grade: low.
- Who: the user, through an ordinary action.
- Cost: in the plain case nothing, since it only blocks a no-op. In the edge case, one extra transaction (about 0.17 ₳).
- Way out: delegate to another pool or DRep (or always abstain) and then back. Registering the account's own DRep again delegates regardless. A site over CIP-30 can also do it.
