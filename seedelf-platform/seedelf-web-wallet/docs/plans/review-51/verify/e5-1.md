# e5#1: verification

From lane E5, graded low by its finder.

## Trace: partly, low

The main claim holds in full; the Byron claim holds only in a narrower case.

**Type 2 (key payment, script stake part): holds as described.** Core's `is_payable_address` refuses any Shelley address with a script in either part, because Pallas's `has_script` counts the stake part too. Send's and Make public's To field refuse such an address, a `$handle` held at one, and saving it as a contact, all with "That's a script's address … could be locked there for good". That is false: only the payment key spends the output, and the ledger and the deployed `wallet.ak` take it with no datum. I found no guard, caller or type that avoids the refusal. My test fails on TREE for exactly this reason.

**Byron: holds only in part.**
- The words "That isn't a Cardano address." are false everywhere.
- The refusal blocks a payment the ledger would take only on public Send, and on Contacts, which feed it. Public Send is key-witnessed with no scripts.
- Make public is a Plutus V3 spend. A script transaction can't carry a Byron output: the ledger refuses it in the script context (ByronTxOutInContext), and the wallet's own evaluator, uplc 1.1.23, reaches `unreachable!()` on it. So refusing a Byron address there is right; only the words are wrong.
- The finder's "the user can't pay either kind … on either side", and its fix "accept `Address::Byron`" in the shared core predicate, are wrong for the private side.

**One correction to the finder's evidence.** A test does pin the type-2 shape: `seedelf-core/tests/mint_test.rs:2484-2502` asserts `script_stake` is refused. Only `extension/tests` has none.

**Severity: low.** Only the user can reach it, by an ordinary payment to a rare address shape. Nothing is lost, locked or misdirected; the payment is refused with false words. There is a way out: the phrase restores in any CIP-1852 wallet for public funds. For private funds, the user can Make public to their own address first, which links the two: a small cost in an edge case.

**Byron: don't use the finder's fix.** Accepting `Address::Byron` in the shared core predicate would let `sweep`/`sweep_many` (Make public) and `remove` build a Plutus V3 spend with a Byron output, and that fails twice:
- The ledger can't put a Byron output in a script's context (ByronTxOutInContext, a phase-1 refusal).
- The wallet's own evaluator, uplc 1.1.23, hits `unreachable!()` in `Address::to_plutus_data` (`to_plutus_data.rs:130`). In WebAssembly that panic is a trap, and a trap locks the wallet.

Accept Byron only in the account path (`account_send_many`, public Send's `SendTo::read`), which runs no scripts. That needs three things:
- base58 parsing beside `from_bech32`;
- the network read from the address's attributes, which `cip30.rs:92-109 network_of` already does;
- sizing the output without `to_bech32`, since `minimum_address_payment` at `build.rs:3307-3309` fails on Byron today.

On Make public, refuse a Byron address in true words, for example that the private balance can't pay a Byron address. That takes its own WebAssembly message and a new key in `destination.ts`, because `destination.ts:97` maps every refusal it doesn't recognise to `worker.address.script`. A new WebAssembly sentence alone would read as "a script's address".

// Chunk 51, finding e5#1 (merged into r2a#1, whose core test is seedelf-core/tests/r51_r2a_1.rs).
//
// The extension's side of it. Send's and Make public's To field (resolve-destination, resolveDestination,
// checkPayable, then WebAssembly's checkPayableAddress) and Contacts (contacts.ts check, checkPayable) refuse a key
// address whose stake part is a script (CIP-19 header type 2, addr_test1y…) as "That's a script's address … could be
// locked there for good", though only its payment key can spend it and the ledger takes the output with no datum.
// And they call a Byron address "not a Cardano address".
//
// The right behaviour, asserted here: the type-2 address is read as anyone's payable address, passes WebAssembly's own
// check (which public Send's and Make public's builders run again), and is saved as a contact; a script payment part
// is still a script's address; and a Byron address is never called no Cardano address (Make public can't pay one,
// since a script's transaction can't carry a Byron output, but it is an address).
import { describe, expect, it } from "vitest";

import { bech32, bech32Bytes } from "./fixtures/bech32";
import { loadTestWasm, testBalances, vectors } from "./fakes";

const PASSWORD = "correct horse battery";
const account = (words: number) =>
  vectors("cardano_account.json").find((v) => v.account === 0 && v.phrase.split(" ").length === words)!;
/** The 15-word phrase's receive address: someone else's base address, payment key and stake key (header 0x00). */
const THEIRS = account(15).preprod.receive_0 as string;

/** THEIRS's own 56 bytes of hashes under another header: 0x20 reads its stake key hash as a script hash. */
function withHeader(header: number): string {
  const bytes = Uint8Array.from(bech32Bytes(THEIRS));
  bytes[0] = header;
  return bech32("addr_test", bytes);
}
/** CIP-19 type 2 on a test network: THEIRS's payment key, a script (a multisig's stake script, say) as its stake part. */
const KEY_STAKED_BY_SCRIPT = withHeader(0x20);
/** CIP-19 type 1: a script's payment part, a key's stake part. A script's address indeed. */
const SCRIPT_STAKED_BY_KEY = withHeader(0x10);
/** A mainnet Byron (Icarus) address: pallas-addresses 0.35.1's own test vector (src/byron.rs). */
const BYRON = "Ae2tdPwUPEZLs4HtbuNey7tK4hTKrwNwYtGqp7bDfCy2WdR3P6735W5Yfpe";

async function unlocked() {
  const t = testBalances();
  await t.wallet.create(account(12).phrase, PASSWORD);
  return t;
}

/** What a promise gives, or the words it's refused with. */
const outcome = <T>(p: Promise<T>) => p.then((value) => value as T | string, (e: Error) => e.message);

describe("r51 e5#1: a key address whose stake part is a script", () => {
  it("control: the fixture's addresses are well formed, a key/key address is anyone's, a script payment part is a script's", async () => {
    const t = await unlocked();
    const bytes = bech32Bytes(THEIRS);
    expect([bytes.length, bytes[0]]).toEqual([57, 0x00]);
    expect(bech32("addr_test", bytes)).toBe(THEIRS);
    expect(KEY_STAKED_BY_SCRIPT.startsWith("addr_test1y")).toBe(true);
    expect(SCRIPT_STAKED_BY_KEY.startsWith("addr_test1z")).toBe(true);
    expect(await t.withdraw.resolve("preprod", THEIRS)).toEqual({ address: THEIRS, own: false });
    await expect(t.withdraw.resolve("preprod", SCRIPT_STAKED_BY_KEY)).rejects.toThrow("That's a script's address.");
  });

  it("is read as anyone's payable address in Send's and Make public's To field", async () => {
    const t = await unlocked();
    expect(await outcome(t.withdraw.resolve("preprod", KEY_STAKED_BY_SCRIPT))).toEqual({
      address: KEY_STAKED_BY_SCRIPT,
      own: false,
    });
    expect(t.koios.calls).toHaveLength(0);
  });

  it("passes WebAssembly's own check, which public Send's and Make public's builders run again", () => {
    const wasm = loadTestWasm();
    let refused: string | undefined;
    try {
      wasm.checkPayableAddress(KEY_STAKED_BY_SCRIPT, wasm.Network.Preprod);
    } catch (e) {
      refused = e instanceof Error ? e.message : String(e);
    }
    expect(refused).toBeUndefined();
  });

  it("is saved as a contact", async () => {
    const t = await unlocked();
    const saved = await outcome(
      t.contacts
        .save("preprod", { name: "Carol", value: KEY_STAKED_BY_SCRIPT })
        .then((list) => list.map((c) => [c.name, c.kind, c.value])),
    );
    expect(saved).toEqual([["Carol", "address", KEY_STAKED_BY_SCRIPT]]);
  });
});

describe("r51 e5#1: a Byron address", () => {
  it("is never called no Cardano address", async () => {
    const t = await unlocked();
    // Pinned: what isn't an address at all still says so.
    await expect(t.withdraw.resolve("mainnet", "nope")).rejects.toThrow("isn't a Cardano address");
    const said = await outcome(t.withdraw.resolve("mainnet", BYRON));
    expect(typeof said === "string" ? said : "").not.toContain("isn't a Cardano address");
  });
});
