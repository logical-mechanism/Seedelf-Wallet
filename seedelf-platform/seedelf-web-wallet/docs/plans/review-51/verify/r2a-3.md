/// A wallet-contract UTxO owned by `w`, made by the transaction `[a, b; 32]`,
/// holding one of each token named in `names` (raw bytes), as Koios lists it.
fn owned(w: &World, a: u8, b: u8, lovelace: u64, names: &[Vec<u8>]) -> UtxoResponse {
    let register = w.owner.clone().rerandomize().unwrap();
    let mut hash = [a; 32];
    hash[31] = b;
    UtxoResponse {
        tx_hash: hex::encode(hash),
        tx_index: 0,
        address: w.wallet.to_bech32().unwrap(),
        value: lovelace.to_string(),
        payment_cred: hex::encode(w.chain.config.contract.wallet_contract_hash),
        inline_datum: Some(InlineDatum {
            bytes: hex::encode(register.to_vec().unwrap()),
            value: json!({
                "constructor": 0,
                "fields": [{"bytes": register.generator}, {"bytes": register.public_value}]
            }),
        }),
        asset_list: Some(
            names
                .iter()
                .map(|name| KoiosAsset {
                    decimals: 0,
                    quantity: "1".to_string(),
                    policy_id: TOKEN_POLICY.to_string(),
                    asset_name: hex::encode(name),
                    fingerprint: String::new(),
                })
                .collect(),
        ),
        ..Default::default()
    }
}

/// The least the ledger takes for one output at the contract's address
/// holding one of each of `names` under an inline register: what a stranger
/// pays the Seedelf, at the least.
fn least_on_chain(w: &World, names: &[Vec<u8>]) -> u64 {
    let policy: [u8; 28] = hex::decode(TOKEN_POLICY).unwrap().try_into().unwrap();
    let register = w.owner.clone().rerandomize().unwrap();
    let mut output =
        Output::new(w.wallet.clone(), 5_000_000).set_inline_datum(register.to_vec().unwrap());
    for name in names {
        output = output.add_asset(Hash::new(policy), name.clone(), 1).unwrap();
    }
    calculate_min_required_utxo(output, &w.chain.params).unwrap()
}

## Impact: partly, medium

The mechanism and the figures hold. A stranger's 200-token bundle D (4,068,640 lovelace) can only be re-made as change 20 tokens an output: 10 contract outputs at 1,857,610 each, 18.58 ₳ in all. History-aware order a puts D (Received, tier 0) ahead of the boxes (tier 2). So a 35 ₳ Make public builds only at k = 6, spending O1, D and B1-B4, where O1 + B1 + B2 pays with ADA-only change. The margins (Short at 53.20 ₳ by about 0.9 ₳) don't turn on the fee estimates.

What the user gets:
- About 14.5 ₳ of their own ADA ends up as the least of junk outputs.
- About 0.2 ₳ more fee.
- Two more boxes merged than the payment needed, which can't be undone.
- The stranger's tokens now mark 10 of their change outputs.

The review shows only the fee, the balance before and after (which counts the bound ADA) and the histories note. That note names the 4 boxes merged but not that fewer would pay. Nothing warns about the ADA. No Seedelf Wallet or CLI builder can free it: deposit_outputs, change_outputs and pay_address all split 20 an output.

Where it is narrower than claimed:
1. The ADA isn't lost. It stays in the balance, and the user can get it back outside the product: make the tokens public to another wallet, which packs them into one output (about 4 ₳), at a fee and a privacy cost. A pack-by-size fix would also free it.
2. Coin control keeps D out of every spend if the user locks it (coin-control.ts:259-262, applied in readContract). The finding doesn't mention this, but nothing tells the user D is costly.
3. Max keeping the tokens' least is the owner's chunk-34 call, so that part is known; only the size of the re-chunk cost is new. Also, Make public's Max (Everything) sends the junk to the destination with about 13.8 ₳ rather than keeping 18.58 ₳. The 18.58 ₳ figure is a private Send's Max (transfer_most).
4. In the 800-token case, 15.3 ₳ of the 77.7 ₳ is the stranger's own deposit. About 62.5 ₳ is the user's, and only when the merging order holds that much more; otherwise it's r2a#2's refusal.
5. Only a deliberate stranger with custom tooling can set it up, at about 4.5 ₳ for no gain, and 4.07 ₳ of that lands in the victim's balance. Seedelf Wallet, the CLI and airdrop tools never make an output of more than 20 tokens at a Seedelf.

It stays medium. The trigger is the brief's baseline stranger plus an ordinary payment, in a shape common for Lovejoin users (any payment that reaches past Own, Session and ADA-only Received money). It's real money with no way back inside the product and no warning, plus a privacy cost by default. Max's later note even calls the 18.58 ₳ 'the least ADA they need', against the ledger's ~4.2 ₳ for one output. The owner already treated the same class as a defect on session returns (independent review H1/H2: plan_return's cost rule, and 'leaving someone else's tokens behind is also the private default'). It isn't high: funds aren't stranded outright, they stay the user's, and the user's own payment is needed. It isn't low: the cost isn't small, and a stranger's UTxO is the brief's normal case, not an edge.
