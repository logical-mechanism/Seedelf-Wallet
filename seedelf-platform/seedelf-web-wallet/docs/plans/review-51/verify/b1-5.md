## Trace: confirmed, low

Every claim traces in TREE, and I found no guard. None of the five workflows names any third-party action by commit. dtolnay/rust-toolchain@master is step 2 of each of release.yml's three signing jobs, so it runs before the build, the key import and the signing. It also sets up the rustc and cargo that the build step runs, so the genuine key signs whatever that toolchain compiled.

softprops/action-gh-release@v2 runs in finalize-release with GITHUB_TOKEN. release.yml declares no permissions, so that token gets the repository default, which web-wallet.yml:25-26 says is write. It also runs after the same job has imported the release key and signed with it. data-layer-deploy.yml's build job compiles the VPS binary with the same @master, and the vps job ships it with a checksum made in that same build job. web-wallet.yml and data-layer.yml are read-only and use no secrets, so as the finder says, their pins can only falsify a CI verdict.

What I looked for and didn't find: a SHA anywhere, a dependabot.yml, or any attestation or provenance step. RELEASE.md's user checks (gpg --verify and sha256) compare only against what the same job produced.

It isn't known. Nothing in the backlog, the archived reviews, the plans, the other chunk 51 lanes or the owner's memory covers action pins. Launch review #61's supply-chain fix covered Cargo.lock and the Rust pin, not action refs. SECURITY.md:41 excludes vulnerabilities in our dependencies from the bounty. Our own choice of a movable ref is a different thing, and it can be fixed in our code (SECURITY.md:32).

Grade: who is nobody. It takes the owner of one of four third-party repositories, or someone who takes over that account, moving a ref. That class happened at scale in the tj-actions/changed-files compromise of March 2025. If it happened, the cost would be high: CLI binaries signed by the genuine key that users cannot tell from real ones, and the key sitting on the same runner as that code. Users have no way to detect it. On the brief's scale, though, this is "a missing check with no reachable harm today", so low, which matches the finder.

```
// Chunk 51, b1#5. An action a workflow names runs as the job: with its token, beside
// the secrets its steps use, and before the steps that come after it. A tag or a branch
// (`@v2`, `@master`) is a pointer its owner, or whoever takes their account, can move to
// other code at any time; only a full commit SHA names fixed code. release.yml's three
// build jobs set up Rust with dtolnay/rust-toolchain@master, then build, import the
// release key and sign what that toolchain built; finalize-release runs
// softprops/action-gh-release@v2 with the token, after its own key import and signing;
// data-layer-deploy.yml's build job makes the binary the VPS runs with the same @master.
// So every third-party action, an owner other than GitHub's own `actions/` and
// `github/`, must be pinned by a full 40-character commit SHA. A local action (`./`) is
// this commit's own; a `docker://` image must name its digest.

import { readdirSync, readFileSync } from "node:fs";

import { expect, it } from "vitest";

const WORKFLOWS = new URL("../../../../.github/workflows/", import.meta.url);
const FIRST_PARTY = new Set(["actions", "github"]);

type Use = { file: string; where: string; ref: string };

/** Every `uses:` in every workflow, step or reusable-workflow job, with its file:line. */
function uses(): Use[] {
  const files = readdirSync(WORKFLOWS)
    .filter((f) => /\.ya?ml$/.test(f))
    .sort();
  return files.flatMap((file) =>
    readFileSync(new URL(file, WORKFLOWS), "utf8")
      .split("\n")
      .flatMap((line, i) => {
        const m = /^\s*(?:-\s+)?uses:\s*["']?([^"'\s#]+)/.exec(line);
        return m ? [{ file, where: `${file}:${i + 1}`, ref: m[1] }] : [];
      }),
  );
}

function pinned(ref: string): boolean {
  if (ref.startsWith("./")) return true;
  if (ref.startsWith("docker://")) return /@sha256:[0-9a-f]{64}$/.test(ref);
  if (FIRST_PARTY.has(ref.split("/")[0])) return true;
  return /@[0-9a-f]{40}$/.test(ref);
}

it("pins every third-party action by a full commit SHA, in every workflow", () => {
  const all = uses();
  // Not vacuous: the scan reached the workflows, the signing one and the deploy one among them.
  expect(all.length).toBeGreaterThan(0);
  expect(all.some((u) => u.file === "release.yml")).toBe(true);
  expect(all.some((u) => u.file === "data-layer-deploy.yml")).toBe(true);

  const loose = all.filter((u) => !pinned(u.ref)).map((u) => `${u.where} ${u.ref}`);
  expect(loose).toEqual([]);
});
```
