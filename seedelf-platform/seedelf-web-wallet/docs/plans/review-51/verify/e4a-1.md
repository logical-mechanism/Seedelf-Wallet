# e4a#1: verification

From lane E4a, graded low by its finder.
Also reported as e6#2.

## Trace: confirmed, low

Both reports hold as described. I traced the path end to end and a test shows it: on TREE, 7 of its expectations fail. With the finder's fix sketch applied to balances.ts in a copy, all 7 pass.

The mechanism:
- A balance reading makes its network calls outside the wallet's queue.
- Its final step checks only `keys.account !== index` (balances.ts:392). That is 0 for both phrases, because a restore starts on account 0 (`useFirst`).
- Its in-flight key is `${network}:${account}` (balances.ts:211), with nothing of the wallet in it.
- The BalanceService is built once per worker (sw.ts:192), and Remove wallet never touches it (handlers.ts:254-282).

So a reading begun under phrase A, whose account read is still out after Remove wallet and a restore of B, plays out like this:
1. It is handed to B's Home, because `shared()` returns the pending promise (it does on Refresh too).
2. It is kept as B's reading, with A's UTxOs and A's addresses.
3. `activity.arrived` (:399, unguarded) seals A's private UTxOs into B's `history.<net>`. They stay in B's private Activity after a Refresh.
4. That uses up the new history's `first` mark, so B's own earlier private UTxO is noted as a payment received rather than Unknown. This breaks the restore rule in privacy.md:173 (the e6#2 part).

contract-scan's `same(keys)` doesn't help: it guards only while the contract read runs, and here that read finished before the reset.

One consequence neither finder named: the kept A payment keys are trusted as given. They feed the wasm `is_own_address` (lib.rs:5111-5116, a match on `known` returns true), tx-view's `accountKeys` and dapp's `publicKeys`. So until B's next whole reading, Send and Make public call an address of A's "own" ("it comes back, less the fee"). The test shows `own: true`.

Not settled or known anywhere I searched.

Grade: low.
- **Who:** the user alone. A site's reads go through dapp.ts, a stranger can't open the window, and Koios is honest here, only slow.
- **Window:** narrow. A's account or stake read must outlast a Remove wallet plus a restore, about 15–30 s for a quick user, while the contract part finished first. On mainnet the data layer answers within its 10 s cap. So it needs Koios-only (Remove wallet keeps that switch), the public part held on Koios, or preprod: Koios's 45 s timeout, two retries and 429 holds of up to 60 s.
- **No funds lost:** every build reads fresh with B's keys. A payment to A's address goes to the other phrase, which in the one-user case is the user's own other wallet.
- **Wrong figures, then a way out:** B's Home, the UTxOs screen and Public activity show A's money. That lasts until Refresh, or until Home mounts with a reading over a minute old (Home.tsx:381).
- **What has no way out short of another Remove wallet:** the sealed history keeps A's receipts (amounts and tx hashes) as "Already in your private balance". B's earlier UTxOs are misclassed as "Received", one history each. That makes coin selection more cautious, not less, so no link is made by default.
- **Shared browser:** A's private side is shown to whoever restores next.

The persistent history and the own-address label put it at the top of low, not medium.

**Fix notes:**

Tie each reading to the wallet it began under, as contract-scan's `same(keys)` and the restore scan's C16 `pin` do.

1. In `reading()` (balances.ts:203-214), take an identity in the same `withKeys` turn. The options are a phrase id (contract-scan's `ownerOf(keys)`, or `keys.oneTime.keyHash(0)`), or an epoch the Wallet bumps in `open()` and `wipe()`.
2. Put that identity in the in-flight key, `${network}:${account}:${id}`, so another phrase's Home never joins the reading.
3. Pass it to `read()` and `readPrivate()`. In the final `withKeys`, keep nothing when it differs (balances.ts:392, and :265 in readPrivate), and skip `activity.arrived` (:399, :278). Skip `readingNoted`'s failure note too (:160-165).
4. As a belt-and-braces step, clear `inFlight`, `inFlightPrivate` and `failedWords` in handlers.ts reset-wallet, beside `ctx.sessions.reset()` (:277).
5. For the sealed record, the class fix is to give `arrived` the owner it was read for, as contract-scan's `Settled.owner` does, so `history.<net>` refuses rows read for another phrase.

The sketch I ran used the Keys object's identity, kept in a WeakMap id, plus a stale flag; all 7 assertions pass with it. Keys identity also changes on a lock and unlock of the same phrase, and on an account switch. Such a reading would then be dropped, not kept, which is harmless; a phrase id or epoch is finer.

Members of the same family to check against that identity:
- dapp.ts `view()`'s shared `reading` map, keyed by network and account.
- `ActivityService.cardano`'s final write (activity.ts around :562). The finder says its pages are reused only for the same key set; I didn't verify it.
- accounts.ts `discover`/`check` → `merge`.

Consumers that trust the kept keys as given: the wasm `is_own_address` (lib.rs:5111-5116), tx-view.ts `accountKeys` (:218-225), dapp.ts `publicKeys` (:2415-2419) and lovejoin.ts `accountKeys` (:6321). They are safe once `keep` is tied to the phrase. A defensive extra is to store the owner with `seedelf.accountAddresses.<net>` and ignore it on a mismatch.

The fix needs no owner call: it adds no refusal and changes no privacy default and nothing a screen offers.

// Chunk 51, finding e4a#1 (reported again as e6#2): a balance reading that spans Remove wallet and the restore of
// another phrase. A reading asks Koios outside the wallet's queue, and its last step checks only the public account's
// index, 0 for both phrases. The BalanceService, and the readings it has in flight, outlive the reset. So the reading
// begun under phrase A is handed to phrase B's Home and kept as B's reading, whose keys then make A's addresses read as
// B's own. A's private UTxOs are sealed into B's history, and that uses up its first-reading mark, so B's own UTxO from
// before is then noted as a payment received.
// Each expectation is the right behaviour, and each fails on the tree as it is (soft, so the run shows them all).
import { describe, expect, it, vi } from "vitest";

import { SESSION_ACCOUNT_ADDRESSES_PREFIX, type AccountAddresses } from "../src/background/activity";
import { handle, type Context } from "../src/background/handlers";
import type { KoiosUtxo } from "../src/background/koios";
import { NetworkChoice } from "../src/background/preferences";
import { SESSION_BALANCES_PREFIX } from "../src/background/wallet";
import type { NetworkName } from "../src/networks";
import { UNKNOWN } from "../src/shared/histories";
import type { ActivityEntry, Balances, Message, Status } from "../src/shared/rpc";
import { koiosPreprod, loadTestWasm, ownedUtxos, testBalances, vectors } from "./fakes";

const PASSWORD = "correct horse battery";
const vector = (words: number, last: string) =>
  vectors("cardano_account.json").find(
    (v) => v.account === 0 && v.phrase.split(" ").length === words && v.phrase.endsWith(` ${last}`),
  )!;
/** Owns owned-utxos.json's contract UTxOs (28 ₳ counted, and a Seedelf), and a recorded preprod account. */
const A = vector(12, "about").phrase as string;
/** A's first receiving address. */
const A_RECEIVE = vector(12, "about").preprod.receive_0 as string;
/** No account on preprod, and one contract UTxO of its own (below). */
const B = vector(24, "title").phrase as string;

type T = ReturnType<typeof testBalances>;

function context(t: T): Context {
  const networks: NetworkName[] = ["preprod", "mainnet"];
  return {
    ...(t as unknown as Context),
    wasm: loadTestWasm(),
    connector: async (on) => on,
    version: "1.0.0",
    network: "preprod",
    networks,
    networkChoice: new NetworkChoice(t.local, networks),
  };
}

const ask = (message: Message, ctx: Context) => handle(message, ctx);

/** A contract UTxO under a fresh re-randomization of `words`' Seedelf register: 9 ₳, made long before this device. */
function contractUtxoOf(words: string, txHash: string): KoiosUtxo {
  const wasm = loadTestWasm();
  const entropy = wasm.phraseToEntropy(words);
  const key = wasm.SeedelfKey.fromEntropy(entropy, 0);
  try {
    const datum = Buffer.from(wasm.registerToDatum(wasm.rerandomize(key.baseRegister()))).toString("hex");
    return { ...ownedUtxos[0]!, tx_hash: txHash, tx_index: 0, value: "9000000", asset_list: [], inline_datum: { bytes: datum, value: {} } };
  } finally {
    key.free();
    entropy.fill(0);
  }
}

/** Holds the first `credential_utxos` asking for the account's payment keys, not the contract's: Koios slow on it. */
function holdAccountUtxos(t: T) {
  const real = t.koios.fetch;
  let release!: () => void;
  let reached!: () => void;
  const gate = new Promise<void>((r) => (release = r));
  const hit = new Promise<void>((r) => (reached = r));
  let once = true;
  t.koios.fetch = async (url, init) => {
    if (once && new URL(url).pathname.endsWith("/credential_utxos")) {
      const asked: string[] = JSON.parse(String(init.body))._payment_credentials;
      if (!asked.includes(koiosPreprod.wallet_contract)) {
        once = false;
        reached();
        await gate;
      }
    }
    return real(url, init);
  };
  return { hit, release };
}

describe("a balance reading still running when the wallet is removed and another phrase restored (r51 e4a#1, e6#2)", () => {
  it("is never the new phrase's: not handed to its Home, not kept as its reading, not sealed into its history", async () => {
    const t = testBalances();
    const ctx = context(t);
    const bOwn = contractUtxoOf(B, "b1".repeat(32));
    t.koios.added.push(bOwn);
    expect(((await ask({ type: "create-wallet", phrase: A, password: PASSWORD }, ctx)) as Status).state).toBe("unlocked");

    // The contract's part ends first and is kept; the account's UTxOs are slow at Koios.
    let contractKept = false;
    const set = t.session.set.bind(t.session);
    t.session.set = async (key, value) => {
      if (key === "seedelf.contract.preprod") contractKept = true;
      await set(key, value);
    };
    const hold = holdAccountUtxos(t);
    // A's Home asks for its first reading.
    const left = ask({ type: "balances" }, ctx);
    await hold.hit;
    await vi.waitFor(() => expect(contractKept).toBe(true), { timeout: 10_000 });
    // The stake key's standing, asked beside them, answers meanwhile (in memory here: a few turns of the event loop).
    await vi.waitFor(() => expect(t.koios.calls.some((c) => c.path === "account_info")).toBe(true), { timeout: 10_000 });
    for (let i = 0; i < 20; i++) await new Promise((r) => setTimeout(r, 5));

    // Settings' Remove wallet, then a restore of phrase B, which starts on account 0 as A was.
    expect(((await ask({ type: "reset-wallet", force: true }, ctx)) as Status).state).toBe("no-wallet");
    expect(((await ask({ type: "restore-wallet", phrase: B, password: PASSWORD }, ctx)) as Status).state).toBe("unlocked");
    // B's Home asks while A's reading is still out; then Koios answers A's.
    const shown = ask({ type: "balances" }, ctx);
    hold.release();
    await left.catch(() => undefined);
    const b = (await shown) as Balances;
    const bStake = await t.wallet.withKeys(({ cardano }) => cardano.stakeAddress(t.deps.wasm.Network.Preprod));

    // B's Home shows B's money: its own 9 ₳ private UTxO and an empty account. Never A's 28 ₳, A's Seedelf, A's account.
    expect.soft(b.seedelf, "B's Home: private side").toMatchObject({ lovelace: "9000000", utxos: 1, seedelfs: [] });
    expect.soft(b.cardano, "B's Home: public side").toMatchObject({ lovelace: "0", utxos: 0 });
    // What's kept for B's next look (Home, the UTxOs screen, Public activity) is B's, never A's reading or addresses.
    const kept = await t.wallet.withKeys(() => t.session.get<Balances>(SESSION_BALANCES_PREFIX + "preprod"));
    expect.soft(kept?.seedelf.lovelace, "kept reading: private side").toBe("9000000");
    const addresses = await t.wallet.withKeys(() => t.session.get<AccountAddresses>(SESSION_ACCOUNT_ADDRESSES_PREFIX + "preprod"));
    expect.soft(addresses?.stake, "kept addresses: stake key").toBe(bStake);
    // The kept keys also say which addresses are the account's (destination.ts ownAccount, the wasm is_own_address):
    // Send and Make public never call an address of A's this account's own, "it comes back, less the fee".
    const destination = (await ask({ type: "resolve-destination", to: A_RECEIVE }, ctx)) as { own: boolean };
    expect.soft(destination.own, "Send: A's address as B's own").toBe(false);

  });
