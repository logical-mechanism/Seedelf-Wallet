# x2#2: verification

From lane X2, graded low by its finder.

## Trace: confirmed, low

The finding holds as described, and my run shows it. A stranger pays about 1.34 ₳ to the enterprise KEY address whose key hash is the contract's script hash (preprod addr_test1vz2te2wqn85yllvs69grz6a5fsc60pczywg8dg9gp6j2g6ghn7njf, mainnet addr1vx2te2wqn85yllvs69grz6a5fsc60pczywg8dg9gp6j2g6gvm20av), under a re-randomization of the user's public register. No key can ever spend that UTxO.

How the wallet takes it:
- The contract scan asks Koios's credential_utxos by bare hash. The wallet uses that endpoint for key hashes and script hashes alike, so it can only match the 28 bytes, whatever their kind.
- No reader on the path checks the address's payment-part kind: ownedUtxos, spendable, check_spendable, eval::refusal, max_inputs and select_script_inputs all pass it.

What follows:
- The private balance counts the 1.34 ₳.
- Every Seedelf spend gives each input a Spend redeemer. The wallet's own evaluator (uplc phase one, run_phase_one = true) refuses the one on the key-locked input, before anything is signed or sent.
- For a private balance of 20 UTxOs or fewer, Max puts every UTxO in one part, so Max is refused outright, in uplc's words.

Run on TREE with the real WebAssembly and the worker over the fake Koios:
- Before the row lands: 28,000,000 lovelace over 2 UTxOs, and Max spends both.
- After: 29,340,000 over 3, and Max fails with "The wallet couldn't evaluate the transaction: missing and/or unexpected validator(s) and/or redeemer(s) Missing ø Unexpected Spend[2]".

With a kind-aware ownedUtxos in a copy, the test passes and balances.test.ts and transfer.test.ts still pass.

One detail in the finding is off, and the truth is broader: `apart` never routes around this row. Selection's attempt only builds and estimates, so the row never shows up as a Failed choice. Whichever choice estimates first is measured once, with no retry, so any amount whose chosen set includes it fails, even when the wallet could pay without it.

Grade: low, at the top of low.
- Who: a stranger who knows one of the user's registers. Any Seedelf name makes it public.
- Cost to the stranger: at least 1.34 ₳ burnt per planted UTxO, and they gain nothing.
- Cost to the user: no money is lost, nothing wrong is signed or sent, and no privacy link is made. The balance is overstated by the amount burnt. Max (Send all, Make public all) is refused; for a larger balance it sends only some parts and gives the wrong reason. Some amounts are refused too. All of this lasts until a release fixes the check.
- Way out: lock that UTxO in coin control. It is hard to find, though: the error names an input index, not a UTxO.
- It isn't medium: a way out exists, and the wrong figure is the stranger's own burnt money.
- The owner's launch review graded the reference-script sibling (#12) Medium, but #12 also blocked every session return and broke public sends.

Reach: always on preprod, which reads Koios alone. On mainnet, through Koios: the Koios-only switch, or while the private index is down. Mainnet's default private-index route depends on seedelf-data, which I didn't read.

// Chunk 51, x2#2 (the trace verifier's test). Every Seedelf's register is
// public: its datum is on chain. A stranger re-randomizes one of the user's,
// (g^d, u^d), and pays about 1.34 ₳ (the least that output holds) to the
// enterprise KEY address whose key hash is the wallet contract's script hash,
// with that register as its inline datum. No key has that hash, so nobody can
// ever spend it: the stranger's 1.34 ₳ is burnt.
//
// Koios's credential_utxos takes bare 28-byte hashes, key or script alike
// (koios.ts credentialUtxos), so asked for the contract's it lists this UTxO
// too, and the contract scan (contract-scan.ts:148) reads it. ownedUtxos
// (balances.ts:489) judges a row by its register alone and keeps it, and so
// does WebAssembly's check_spendable (lib.rs:2316). So the private balance
// counts 1.34 ₳ that can never move, and a Seedelf spend that takes it can't
// be built: the builder gives every input a Spend redeemer, and the wallet's
// evaluator (uplc's phase one, run by eval.rs) refuses one on a key-locked
// input. Max takes every UTxO of a balance of 20 or fewer in one part, so Max
// is refused outright, in the evaluator's words.
//
// What's right (the finding's fix): a contract row counts only when its
// payment part is the contract's SCRIPT hash. Then the private balance is
// what it was before the stranger's output landed, and Max pays it as it did.
// Driven through the worker over the fake Koios with the real WebAssembly, as
// transfer.test.ts's "pays the most there is with Max" is.

import { describe, expect, it } from "vitest";

import { CONTRACT_V1 } from "../src/background/balances";
import { registerOf } from "../src/background/chain";
import type { KoiosUtxo } from "../src/background/koios";
import { bech32Bytes, preprodAddress } from "./fixtures/bech32";
import { loadTestWasm, ownedUtxos, testBalances, transferPreprod, vectors } from "./fakes";

const PASSWORD = "correct horse battery";
/** "This is a test.", a live preprod Seedelf the phrase doesn't own. */
const THEIRS = transferPreprod.to;
const hex = (b: Uint8Array) => Buffer.from(b).toString("hex");

/**
 * The stranger's output, as Koios's credential_utxos lists it for the contract's hash: 1.34 ₳ at the enterprise KEY
 * address with that hash, under a fresh re-randomization of the user's register (read off the user's own UTxO).
 */
function planted(): KoiosUtxo {
  const wasm = loadTestWasm();
  const found = registerOf(ownedUtxos[0]!)!;
  const base = new wasm.Register(found.generator, found.publicValue);
  const fresh = wasm.rerandomize(base);
  const datum = `d8799f5830${fresh.generator}5830${fresh.publicValue}ff`;
  base.free();
  fresh.free();
  return {
    ...ownedUtxos[0]!,
    tx_hash: "b2".repeat(32),
    tx_index: 0,
    address: preprodAddress(CONTRACT_V1.walletContractHash),
    value: "1340000",
    // The 28 bytes the endpoint matched, as Koios fills it whatever the credential's kind.
    payment_cred: CONTRACT_V1.walletContractHash,
    block_height: 9_000_000,
    inline_datum: { bytes: datum, value: null },
    asset_list: [],
  };
}

describe("x2#2: a UTxO at a key address with the contract's hash", () => {
  it("isn't the wallet's: the private balance doesn't count it, and Max still pays what the wallet can spend", async () => {
    const v = vectors("cardano_account.json").find((v) => v.account === 0 && v.phrase.split(" ").length === 12)!;
    const t = testBalances();
    await t.wallet.create(v.phrase, PASSWORD);
    t.koios.evaluation = transferPreprod.evaluation;

    const row = planted();
    // The contract's preprod address is header 0x70 (enterprise, SCRIPT payment part); the stranger's is the same 28
    // bytes under header 0x60 (enterprise, KEY payment part), which no key spends.
    expect(hex(bech32Bytes(ownedUtxos[0]!.address))).toBe(`70${CONTRACT_V1.walletContractHash}`);
    expect(hex(bech32Bytes(row.address))).toBe(`60${CONTRACT_V1.walletContractHash}`);
    // Its register is the user's, re-randomized: what the wallet's ownership check accepts.
    const wasm = loadTestWasm();
    const reg = registerOf(row)!;
    const asRegister = new wasm.Register(reg.generator, reg.publicValue);
    let owned = false;
    await t.wallet.withKeys((keys) => void (owned = keys.seedelf.isOwned(asRegister)));
    asRegister.free();
    expect(owned).toBe(true);

    // Before it lands: 25 ₳, and 3 ₳ holding tUSDM, and Max spends both (as transfer.test.ts has it).
    const before = await t.balances.get("preprod");
    expect(before.seedelf).toMatchObject({ lovelace: "28000000", utxos: 2 });
    expect(await t.transfer.build("preprod", [{ to: THEIRS, lovelace: null, tokens: [] }])).toMatchObject({
      max: true,
      inputs: 2,
      left: 0,
    });

    // The stranger's output lands, and Koios lists it beside the contract's own.
    t.koios.added.push(row);

    const after = await t.balances.get("preprod", true);
    expect.soft(after.seedelf, "the private balance, with the stranger's unspendable 1.34 ₳ beside it").toMatchObject({
      lovelace: "28000000",
      utxos: 2,
    });

    const max = await t.transfer
      .build("preprod", [{ to: THEIRS, lovelace: null, tokens: [] }])
      .catch((e: unknown) => (e instanceof Error ? e.message : String(e)));
    expect(max, "Max, with the stranger's output beside the wallet's two").toMatchObject({ max: true, inputs: 2, left: 0 });
  });
});
