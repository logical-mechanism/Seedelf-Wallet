# e9a#1: verification

From lane E9a, graded low by its finder.
Also reported as e8b#6.

## Trace: confirmed, low

The finding holds in all four forms. A token's details offer Send and Make private/public when the side has any free UTxO. They offer it for every token Home lists, including a token whose every unit sits in a locked UTxO. The form is handed the side less what's locked, which doesn't hold that token, so it draws no box for it and nothing can be sent. Yet `waitingFor` counts the typed key as "tokens picked", which makes the empty amount read as fine. The result: Review is off and nothing under it says why. That breaks PY-9's recorded fix ("every disabled Review says why").

I found no guard, filter or test that prevents or covers it. The existing tests cover `waitingFor` alone (tests/payment-forms.test.ts) and the e2e covers only a token that is held (LINK is free).

The narrower "on its way" case holds by trace too, but only once Home's 10-minute hold has passed with the payment still unconfirmed. After a confirmation the worker re-reads what it marked as behind.

It's graded low:
- Only the user can reach it, by an ordinary action: locking a UTxO that holds all of a token while another UTxO on that side stays free.
- No money is lost or misdirected. If the user types an ADA amount, the review lists exactly what goes (ADA alone, no token rows).
- There are ways out: Back, typing an ADA amount, or unlocking on the UTxOs screen. The form's aside does say "· 2 ₳ locked", but not which token.
- What it costs is a dead-end flow, offered for exactly the token the user picked, with no reason given.

It isn't medium, because nothing is stuck for good and no money moves.

**Fix notes:**

- CardanoSend.tsx:125, Transfer.tsx:124, Withdraw.tsx:108 and MoveIn.tsx:62 count `tokensPicked` from the typed keys.

- I checked this in a copy: my test passes and PY-9's test still passes. On its own it says "Enter an amount.", which is true but doesn't say where the token went.

- Home.tsx:572 `tokenAction` could offer Send or Make private/public only for a token in the side's free tokens (`free.<side>.tokens`), and TokenDetails' `blocked` would say why otherwise. That changes what a screen offers, so it's the owner's call too.
