### d1#3 · low · A site's payment into the Seedelf contract under a register-shaped datum that can't be spent is shown as 'without a register: anyone can take', when no one can ever take it

- **Where:** `seedelf-platform/seedelf-web-wallet/docs/privacy.md:336`
- **Who:** site · **Since:** fe8b7748 (chunk 15, 2026-09-24) for the classification; 7cc3f363 (2026-10-02) for the warning's words · **Confidence:** traced

**Scenario:**

A site asks the user to sign a transaction that pays 50 ₳ of the account's to Seedelf Wallet's contract. The output's inline datum is Constr 0 with two 48-byte fields, and the public value is a torsion point, an off-curve point, a point of the wrong length, or the generator is the identity. is_payable fails, so the window shows dappUi.warn.noRegister: 'It pays Seedelf Wallet's contract without a register: whatever goes there, anyone can take.' privacy.md:336 describes the same two cases ('or without one (anyone can take it, and the window warns)'). On chain, the deployed validator treats any two-ByteArray Constr 0 as a Register and runs schnorr.prove, where g1.decompress fails or the equation can't be met. So the 50 ₳ is locked for good, not free for anyone. The amount leaving is shown right and the user is warned it isn't theirs. Only the label of who can take it is wrong. Only an identity public value really is 'anyone can take'. A datum held by hash is called 'none' too, whatever it is.

**Evidence:**

wasm/src/cip30.rs:999-1002 `fn is_register_datum(datum_hex) -> bool { register_datum(datum_hex).is_some_and(|r| build::is_payable(&r)) }`.
cip30.rs:1385-1393 `Address::Shelley(s) if *s.payment().as_hash() == contract_hash => Some(if inline.as_deref().is_some_and(is_register_datum) {"register"} else {"none"} ...)`.
en.json:517 dappUi.warn.noRegister.
Deployed contract, `git show 5b82530:seedelf-contracts/validators/wallet.ak`: `if register is Register { and { schnorr.prove(register.generator, register.public_value, ...)?, ... } } else { True }`. 5b82530:lib/schnorr.ak prove: `generator |> g1.decompress |> g1.scale(z)` and `public_value |> g1.decompress |> g1.scale(c)`: decompress fails on a bad or non-subgroup point, so the script errors.
wasm/tests/cip30_test.rs:1374 a_payment_into_seedelf_says_whether_it_has_a_register covers only a payable register against no datum.
This is a sibling of w2#2, which is the same block mislabelling a key address that carries the contract's hash.

**Fix:**

Split 'none' into the case the ledger lets anyone take (no datum, a datum that isn't a Register, or an identity public value) and a third value for a Register-shaped datum is_payable refuses (locked for good), with words of its own (a critical .warn. string, back-translated). Say all three in privacy.md:336. A datum held by hash can't be judged from the body: say so rather than 'anyone can take'. Fix it together with w2#2, in the same match at cip30.rs:1385.

**Known check:**

Searched backlog.md and archive/plans for 'noRegister', 'without a register', 'is_register_datum' and 'register_datum'. Only flows.md:79, chunk-14 and chunk-15 notes, and W2's lane record (w2#2, a different shape in the same code). Not in the backlog.
