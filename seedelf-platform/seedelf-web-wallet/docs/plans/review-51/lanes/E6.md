### e6#1 · medium · A stranger can plant a Seedelf so Remove preselects the public account and says it 'links nothing new'

- **Where:** `seedelf-platform/seedelf-web-wallet/extension/src/background/minted-by.ts:124`
- **Who:** stranger · **Since:** 8edd7024 (privacy review §3.2, 2026-09-27, before 1.0.0); 362ce1b3 added the account index · **Confidence:** traced
- **Needs the owner:** It changes what Remove preselects: some Seedelfs that default to a side today would choose nothing. Possibly also a line for a Seedelf the device has no record of creating.

**Scenario:**

The victim shares their Seedelf name X; the attacker suspects public address A is theirs. The mint policy at 5b82530 is open and checks no output. So the attacker mints a fresh Seedelf G in one transaction T: output 0 goes to the wallet contract under a re-randomization of X's register, holding G and about 1.5 ₳; output 1 pays A 1 ₳. The victim's wallet counts output 0 as its own (the register is theirs) and lists G among their Seedelfs, with no record of who paid. paidByOf then finds an account UTxO from T, or T listed in the public Activity as 'received', and returns {side: 'account'}. RemoveSeedelf preselects the public account and shows 'Back where this Seedelf's ADA came from: your public account paid for it, so this links nothing new.' A user who removes the unknown Seedelf to get back its ~1.3 ₳ (easier to fall for if the attacker copied the label of the victim's own Seedelf) sends it to A. That transaction proves the owner of G's register, whom only the attacker knows is X's owner, controls A. The attacker has now tied Seedelf X to public account A. Without output 1, the wallet would choose nothing and point the user at the private balance. The same class works on the private side: a planted sibling output under the victim's register makes paidByOf return 'seedelf'. That costs no more privacy than an ordinary dust payment.

**Evidence:**

minted-by.ts:120-127: `const recorded = readPaidBy(held.recorded[tokenName]); if (recorded) return recorded; const mint = utxo.tx_hash; if (held.owned.some((u) => u.tx_hash === mint && u.tx_index !== utxo.tx_index)) return { side: "seedelf" }; if (held.account.some((u) => u.tx_hash === mint) || held.accountTxs.has(mint)) { return { side: "account", account: held.activeAccount ?? 0 }; }`. The comment at minted-by.ts:13 ('A Seedelf's UTxO is only ever spent by its removal, so its transaction is the mint') assumes the wallet's own mint. Nothing stops a stranger minting into the user's register.
balances.ts:404-417 seedelfSide lists every owned UTxO holding a Seedelf token and calls paidByOf(utxo, name, {...held, owned}).
balances.ts:242: `accountTxs: new Set(activity?.entries.map((e) => e.txHash))` takes every Activity entry, 'received' ones included.
activity.ts:839 and 880-882: a stranger's payment to the account is listed as kind 'received'.
RemoveSeedelf.tsx:186: `const to = chosen ?? (otherAccountPaid("account", seedelf.paidBy, accounts) ? undefined : seedelf.paidBy);` preselects it, and removeNote (RemoveSeedelf.tsx:110-125) gives en.json `remove.privacy.backToAccount` = "Back where this Seedelf's ADA came from: {{whose}} paid for it, so this links nothing new."
`git show 5b82530:seedelf-contracts/validators/seedelf.ak`: 'Its an open policy for minting'. Minting checks only the token name from the first input and a quantity of 1, never the outputs.
The register comes from X's public Seedelf UTxO. Any re-randomization of it is the victim's (balances.ts:489-506 ownedUtxos).
privacy.md:136 describes the inference; privacy-review.md §3.2 (lines 536-544) designed it with only the wallet's own mints in mind.
RemoveSeedelf.tsx:1-13's rule: 'When the wallet doesn't know ... nothing is chosen ... the wallet won't make it for them'.

**Fix:**

Use only evidence a stranger can't plant. 'The account paid' should need the account's Activity to list the mint as a transaction the account spent in: an entry with a fee and a kind other than 'received'. That means handing paidByOf the entries, not bare hashes. An account UTxO from the transaction, or a 'received' entry, only shows the transaction paid the account, so drop the `held.account` test. The private side's sibling-UTxO test can be planted too. Either accept it as a lower-harm case (it reveals no more than a dust payment) or require the private history's own entry for that transaction. Otherwise return undefined, so nothing is chosen, as §3.2 decided. Test: in minted-by.test.ts, paidByOf with `account: [{tx_hash: mint}]`, or a 'received' entry for the mint, should return undefined. The current tests at minted-by.test.ts:57 and :61 pin the old behaviour.

**Known check:**

Searched docs/backlog.md, docs/archive/plans/*.md (privacy-review §3.2, usability-review RX-3, chunk-18 and chunk-23 notes), privacy.md, flows.md and architecture.md for paidByOf, minted.?by, 'who paid', gift, planted, "someone else's seedelf", 'stranger's Seedelf', 'sent ... a Seedelf'. Also checked the review-51 lane records (R*, W*). Nothing covers a planted Seedelf or a crafted output steering the who-paid inference.

### e6#2 · low · A balance reading that spans Remove wallet plus a restore is kept as the new wallet's and uses up its first-reading mark

- **Where:** `seedelf-platform/seedelf-web-wallet/extension/src/background/balances.ts:392`
- **Who:** user · **Since:** unknown: the reading was never tied to the phrase. The account-only check came in 4279db80 (1.2.0's release review, C11, in web-wallet/1.6.0) · **Confidence:** traced

**Scenario:**

Mainnet with Koios only, or preprod, or the data layer down. Home starts a reading. The contract catch-up (one request) finishes first, while the account read (account_addresses, then credential_utxos, up to 45 s each plus a retry) is still running. The user removes the wallet, or uses Forgot password, and restores another phrase. Both start on account 0. The old reading then resolves under the new wallet's keys. read() checks only `keys.account !== index` (0 === 0), so keep() writes it to session storage as the new wallet's reading: the old wallet's stake address, staking and rewards, and its private side. Home shows those until the next reading. Then `activity.arrived(network, view.owned)` runs with no check. It writes the old wallet's contract UTxOs into the new wallet's sealed history (`history.<net>`) as 'Already in your private balance' entries, and drops that history's `first` mark. At the restored wallet's own first real reading, `h.first` is gone, so its UTxOs are noted as payments received, one history each (receivedIn), not as one Unknown history. privacy.md's restore rule is broken: Activity calls the user's own earlier Make privates 'Received', and coin selection treats them as received money. No money is lost: every build reads the account fresh.

**Evidence:**

balances.ts:363-366 derives `stake` under the keys at the start. account.ts:107-115 reads `withAccount` again after account_addresses returns, so discovery can run under whichever wallet holds the keys by then.
balances.ts:376-397: `const reading = await wallet.withKeys(async (keys) => { ... if (keys.account !== index) return { balances, unkept }; ... if (await keep(session, network, balances, utxos, addresses)) return { balances }; ...})`. It checks only the account index.
balances.ts:399: `await this.deps.activity?.arrived(network, view.owned)`, unguarded.
contract-scan.ts:132-138 `same(keys)` (object identity) guards the contract read only while it runs. A view finished before the reset passes.
activity.ts:631-636: a missing history starts as `{ entries: [], seen: [], first: true, startedAt: now }`. activity.ts:434-449: the first call notes everything with `origin: UNKNOWN` and returns `{entries, seen}` without `first` (466-469). A later call has `h.first` undefined, so there's no origin, and classOf gives receivedIn (activity.ts:656-657).
handlers.ts:254-282 reset-wallet calls wallet.reset() and ctx.sessions.reset(). Nothing ends the BalanceService's or ActivityService's reads in flight.
The same race was fixed for its sibling: sessions.ts:2777-2787's `pin` ties the restore scan to its phrase by key hash ('the wallet removed and another phrase restored meanwhile ... throws as a lock does', 1.5.0's release review C16; keys-and-accounts.md:88).

**Fix:**

Tie each reading to the phrase it began under, as scanNow's `pin` does. Take an id in the first withKeys (contract-scan's `ownerOf(keys)` or `keys.oneTime.keyHash(0)`) and compare it at the keep as well as the account index. On a mismatch, neither keep nor call `arrived`. Do the same in readPrivate (balances.ts:251-280), readingNoted's failure note (balances.ts:149-170) and ActivityService.cardano's final write (activity.ts:562). Give `arrived` the owner it was read for, so it refuses another phrase's rows. Alternatively, have wallet.reset()/create() bump a generation number that these compare. Test: resolve a balances read's credential_utxos only after wallet.reset() and wallet.create(otherPhrase). Expect nothing kept in seedelf.balances.<net> and the new history.<net> still carrying `first`.

**Known check:**

Searched backlog.md, docs/archive/plans and keys-and-accounts.md for 'another wallet restored', 'another phrase restored', 'restored meanwhile', 'reset during/while a read', 'keys it started with'. Found only the restore scan's C16 fix and contract-scan.ts's own comment. Nothing covers the balance reading, Activity's write, or the history's first reading.

## Checked and holds

- registerOf (chain.ts) and seedelf-koios register_of_datum accept the same shapes: tag 121, or 102([0, fields]); definite or indefinite lists; whole or chunked 48-byte strings; no trailing bytes; non-minimal heads in both. JS's float argument can't round a large head down to 121, 102, 2, 0 or 48.
- Ownership needs g^x == u, compared on canonical lowercase hex, with neither point the identity and both in the prime-order subgroup (blstrs 0.7.1 from_compressed checks is_torsion_free). A stranger's identity, small-subgroup or non-canonical register is never counted as ours.
- The index path (utxoOf) and the Koios path give WebAssembly the same row shape. A row with a reference script is never priced. Nothing reads a row's stake_address (rg).
- The private index's folding: only rows and spends at or below the stable cursor are sealed, rows above it carry in `checked`, so no duplicate or lost row across answers. Rollbacks above the cursor drop out. Names are checked against the row's own token, and the wallet's own rows override names from another block.
- Account switch: WIPED_ON_SWITCH clears every per-network reading key. Readings are keyed network:account and never kept for an account left (balances.ts:392, 265). Activity's pages begin again when the key set differs. Per-network keys keep preprod and mainnet apart.
- incomingOf counts each output of the wallet's own sends once: skipped if listed, spent, reserved or conflicting. It counts on a side only with that side's reading kept, and the contract side only under our register and without a Seedelf.
- Address sorting in the lane goes by payment credential and CIP-19 header (odd types are scripts). Pointer and enterprise addresses with our key count, Byron never does, and base(stranger's key, our stake key) is never ours (accountMatcher, paymentOf, pendingEntries). describe's /^addr(_test)?1[zx2w]/ is exactly header types 1, 3, 5 and 7.
- Koios-only switch: every DataLayerKoios method, evaluate, submitTx and privateIndexClient check it on each request. Nothing else calls the data layer (rg for .data.* and new PrivateIndex).
- The fallback matches privacy.md: per part, 5 minutes, 'too large' for that call alone, a paged call restarted whole on Koios. Box origins and pool discovery (txSpends via koiosAlone, launches, firstRegistrations) go to Koios alone. GETs stay no-store, and only data-layer POSTs use cache: default.
- No read in the lane names a private UTxO to a server beyond what privacy.md discloses (tx_status of a watched transaction, and Show image's asset_info). Decimals come from the rows already read, and Seedelf recipients come from the contract view.
- Submit fallback: a data-layer 403/413/415/429/503 or TxSubmitConnectionError goes to Koios at once. A timeout or another 5xx is maybe sent. A lost connection that Koios then calls spent is SpentMaybeSentError. Node refusals stand.
- NFT image: Chrome's grant is checked before anything is asked. A Seedelf's policy is never asked. Only ipfs.blockfrost.dev is fetched; other gateways' CIDs are rewritten to it, path parts re-encoded, '.' and '..' refused. Bodies are capped at 10 MB, sent with no-store, no cookies and no referrer, and shown as a data URI in an <img>. Any other address is only offered to copy.
- Prices: mainnet only, nothing asked with the currency off, rates must be finite and positive, kept in session storage.
- Amounts are exact: sumValue, describe, pendingEntries and the UI's formatQuantity use BigInt. outputsOf quotes every JSON number of 16 or more digits, so quantities above 2^53 stay exact. decodeTx gives decimal strings.
- feed.ts cover() reads a feed only from a cursor kept at or before the transaction's first try (cursors are at least 200 slots behind the tip). One sent before every cursor goes to tx_status alone.
- Contacts: checked on the device (Seedelf by shape, a handle by shape, an address by checkPayable), sealed, per network, saved one at a time.

## Notes

- contract-scan.ts's same(keys) compares the Keys object, and wallet.ts:631-640 makes a new one (and frees the old Seedelf key) on every account switch. So a contract read in flight across an account switch ends as WalletLocked ('The wallet is locked.') although the private balance is the same for every account. Only UX: a retry reads again. Pinning by a key hash, as sessions.ts scanNow's `pin` does, fixes this and e6#2 together.
- contacts.ts inherits destination.ts checkPayable, i.e. WASM payable_address ('not a script, stake or other network's address'). That refuses every script address, including a native-script (multisig) address the ledger pays and whose owners spend without a datum. Chunk 10 chose this ('the output carries no datum') before the owner's 2026-10-19 rule. It's for the Send/Make public lane, or for the owner to confirm as settled.
- DataParts.down(part, holdMs) has no cap on a data-layer 429's Retry-After (data-layer.ts:160-163), while Koios's hold is capped at MAX_BACK_OFF_MS. A bad header from the wallet's own server would keep a part on Koios until the browser closes. The source is trusted, so this is at most a nit. Separately, koios.ts retryAfterMs reads a whitespace-only Retry-After as 0 ms (no cooldown).
- activity.ts KEEP_SEEN is 2,000. A wallet holding more than 2,000 private UTxOs re-notes the evicted outpoints at every reading and rewrites the sealed history each time. It's a cost only: entries for money still held are kept, so no wrong arrival is added.
- A stranger can also plant a Seedelf that carries a reference script or a second Seedelf token. It's listed, but Remove can't build it. The stuck ADA is the stranger's own, so the user loses nothing.
- e6#1's private-side twin: a planted sibling output under the victim's register in the minting transaction makes paidByOf return 'seedelf', and Remove defaults into the private balance with 'links nothing new'. It ties the gift to a new private UTxO, which an attacker could tag with a plain dust payment anyway. Listed in e6#1's fix as the same class.
