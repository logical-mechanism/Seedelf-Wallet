# Chunk 14 plan: style and flow, second pass

Chunk 13 made the wallet a full Cardano wallet with Seedelf built in. This chunk is the second pass over the user's own findings, as chunk 12 was ([plans/chunk-12-style-flow.md](chunk-12-style-flow.md)). Branch `web-wallet/style-flow-2`, one PR into `seedelf-web-wallet`.

**How it runs:** the user tests the built extension and sends findings. Each finding goes in the list below with what was decided. Batches land with side panel and tab screenshots for the user to check before they rebuild.

## Start here

1. `git fetch origin && git checkout web-wallet/style-flow-2`
2. Read this plan and the newest roadmap handoff note.
3. Build and test (from `seedelf-platform/seedelf-web-wallet/extension`): `npm run build && npm test && npm run e2e`.
4. Ask the user for new findings; add them to the list.

## Rules that still hold

- Lace is inspiration for look and flow, not a brand to copy: no Lace purple, fonts or logos (plans/chunk-11-polish.md).
- **Every privacy note stays.** A redesign can move or shorten one, never drop it.
- Correctness UX is always in scope: clear errors, input limits.
- Nothing new phones home. A new host or query needs its own decision, because of what it tells that host.
- **Koios budget.** The wallet uses Koios's public tier: 5,000 requests a day, at most 1,000 rows a response, a 30 s timeout. Every feature states how many requests it costs, and anything paged must scale with the contract's size. The e2e tests assert the exact requests a screen makes.
- The tests find things by role, label and test id. A renamed control means updating `e2e/extension.spec.ts` in the same commit.
- **The name is Seedelf** (item 2): always capitalized, and Seedelf Wallet for the app. `tests/words.test.ts` checks it.

## The list

Items 5 to 13 came from a look at what Lace and Eternl have that the wallet didn't (2026-09-25). The user asked for item 5, and for the rest, except: the dApp connector (its own chunk), a light theme, several accounts, background polling for incoming payments, and NFT images (a better way to fetch them first). Hardware wallets, swaps, buying ADA, voting on proposals and the rest of the README's *Not planned* stay out.

## Review before the PR

A code review of the whole branch, fixed before it went up:

- **Hidden balances held until the settings are read.** Amounts show "••••" until the preferences load, so a screen whose balances arrive first can't show them to someone who hides them.
- **The note counts characters, as core does.** The field cut at 64 UTF-16 units, so emoji stopped at 32; `Note::text()` now returns the note as typed, where it used to rejoin CIP-20's lines with a space even where a line was cut between characters.
- **One home for a Seedelf payment from the account.** `build::account_fund` went: the WebAssembly pays Seedelfs through `account_send_many` with a `Payee::Seedelf`, and its tests (the fresh register, Max, every unsafe register refused) moved there. The docs say so.
- **The side panel's switch to a tab brings back the wallet's tab**, as the toolbar button does (`showWalletTab`, shared with the worker), instead of opening a second one. A start screen (`#create`, `#restore`) still opens a new tab.
- **A recipient paid twice is looked up once** (`destinationResolver`, for Send and Make public), and Activity reads each staking entry's pool from the device once per page.
- Small ones: Create a Seedelf's aside in lower case, as everywhere else, and the Activity token rows masked through `useAmounts`.

**Tests:** Rust workspace green (core `build_test` 16, `note_test` 4); `seedelf-wasm` Node 33; Vitest 222 (+2 skipped); Playwright 41.
